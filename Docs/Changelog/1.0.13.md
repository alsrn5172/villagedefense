# 1.0.13 · 강퇴된 방 재입장 차단

- 날짜: 2026-10-16
- 브랜치: `1.0.13` · 기준: `origin/main 27171d8`(1.0.12 병합 후)
- 상태: 구현·오프라인 검증 완료. Maker 검증은 사용자 담당·대기. PR은 Draft 유지.

## 변경 동작

방장이 참가자를 강퇴하면 해당 방의 서버 원장에 UserId를 기록한다. 강퇴된 사용자는 그 방이 유지되는 동안 재접속하거나 닉네임을 바꿔도 다시 참가할 수 없다. 해당 사용자의 방 목록에서도 숨기며, 오래된 목록이나 직접 참가 RPC로 우회해도 서버가 거절한다.

다른 방에는 입장할 수 있고 직접 방을 만들 수도 있다. 원래 방을 해산하고 새로 만들면 새로운 방이므로 참가할 수 있다. 자진 나가기·일반 접속 종료는 강퇴 기록을 만들지 않는다. 출발 실패로 같은 방이 다시 열릴 때는 강퇴 기록을 유지한다.

- 방 ID: `m_{서버 인스턴스 ID}_{UTC 생성 시각 yyyyMMddHHmmssfff}_{생성 순번}`. 인스턴스 ID 부재 시 GUID 대체. 같은 밀리초에 만들어도 순번으로 구분한다.
- 실제 플레이 룸 키: 기존 `match_{방 ID}_{출발 시도 세대}` 형식을 유지한다.
- 목록 정렬: 복합 ID를 숫자로 해석하던 코드를 생성 순번 정렬로 바꿨다. 강퇴 방은 표시 행 수/더보기 계산 전에 제외한다.
- 강퇴 권한: 방장만 가능하며 자기 자신/없는 토큰/잠금·심장 차감·출발 처리 중 요청은 거절한다. 기존 UI의 잠금 규칙을 서버에서도 확인한다.
- 계정 전체 차단이나 영구 제재가 아니다. 같은 대기 방의 수명 동안만 서버 메모리에 보관하고, 공개 CSV에 강퇴 사용자 명단을 추가하지 않는다.

## 변경 파일

- `RootDesk/MyDesk/Match/MatchLobbyGateway.mlua`: 방 생성·강퇴·참가·목록 필터/정렬. 기존 파일 하나만 변경, 신규 게임 스크립트·UI·CSV·이벤트 없음.
- `Docs/스키마-계약.md`: 서버 원장과 ID/수명 규칙 기록. 기존 공개 CSV·룸 인계 필드 변경 없음.
- `Docs/tools/check-lobby-kick.cjs`, `lobby-kick-cases.lua`: 실제 변경 메서드의 오프라인 회귀 검사.
- 이 보고서. 사용자/Maker가 수정한 Global·Environment·userdataset·UI 파일은 커밋에서 제외한다.

## 검증

- 실제 `MatchLobbyGateway` 메서드를 Lua로 변환해 외부 MSW 서비스만 대체한 오프라인 검증 **216건 통과**.
- 강퇴 통보/이동 중 참가 요청, 반복/오래된 RPC·토큰, 서버 AddMember, 재접속·닉네임 변경, 다른 방·새 방·본인 방 생성, 자진 이탈·일반 재접속, 출발 실패 후 재개를 검사했다.
- 비방장·자기 자신·없는 토큰·잠금/차감/출발 중 강퇴, 기존 정원/해금/진행 중 참가 제한을 검사했다.
- 동일 밀리초 50개 ID, 인스턴스/생성 시각 변경, 인스턴스 ID 부재·구분자 정규화, 실제 룸 키 재시도 세대를 검사했다.
- 사용자별 목록 숨김/생성순 정렬/더보기 계산을 검사했다.
- 프로젝트 정합성 검사 통과(기존 C5 경고 3건). 변경 파일 UTF-8 엄격 디코딩·대체문자 및 공백 검사 통과.

재현: `node Docs/tools/check-lobby-kick.cjs --lua-module <fengari 모듈 디렉터리>`. 검증 의존성은 저장소 밖에 있으며 게임 런타임에 추가하지 않는다.

사용자가 AI는 데이터 정합성만 검사하고 Maker 검증은 직접 맡겠다고 지정한 범위를 유지했다. Maker Refresh/빌드/Play·실제 2인 이동·화면 캡처는 수행하지 않았다. 따라서 위 결과를 Maker 런타임 검증으로 간주하지 않는다. 캡처 증거는 사용자 Maker 검증 후 보완한다.
