### `SchemaVersion` 을 왜 올렸나

`Deserialize` 가 이미 `t["키"] or 기본값` 이라 **필드만 추가하는 변경은 그 자체로 전방 호환**이다.
그래도 1 → 2 로 올린 이유는 **모양이 바뀐 사실을 기록**하기 위해서다 — 나중에
"이 세이브에 무료 스택 필드가 있나" 를 판단할 근거가 버전 말고는 없다.

옛 세이브(필드 없음)는 `freeHeartStack = 2` · `freeAtMs = 0` 으로 읽는다.
**그때는 무료를 쓸 수단이 아예 없었으니 꽉 찬 상태로 시작하는 게 맞다** — 0 으로 주면
"기능이 생기기 전부터 있던 계정만 손해" 가 된다. Codex 2회차가 이걸 버그로 지목했지만
의도된 마이그레이션이라 **채택하지 않았다.**

### 시각은 `DateTime.UtcNow.Elapsed` 다

무료 스택은 **오프라인 동안에도** 차야 하므로 절대 시각을 저장한다.

**🔴 `_UtilLogic.ServerElapsedSeconds` 는 쓸 수 없다.** "월드가 뜬 뒤 경과 시간" 이라
**재시작할 때마다 0으로 돌아간다** — 오프라인 충전이 통째로 깨진다.

이 저장소에 `DateTime.UtcNow` 사용처가 **0건**이었으므로 런타임에서 직접 확인했다:

| 확인 | 값 |
|---|---|
| `DateTime.UtcNow.Elapsed` | `63924642366622` — **서기 1년 기준 절대 ms** |
| `− epoch(1970)` | `1789045568618` = 유닉스 ms. 맞다 |
| 2초 뒤 차이 | `1996` ms. 실제로 흐른다 |

`6.4e13` 은 double 정확 표현 범위(`2^53 ≈ 9.0e15`) 안이라 JSON 왕복에도 정밀도 손실이 없다.

### 🔴 Codex 2회 교차검증에서 잡은 재화 구멍 6개

같은 프롬프트를 **새 세션으로 두 번** 돌려(A·B) 대조하고, 줄번호 8개를 전부 직접 확인했다.
**두 답이 갈린 2건은 내가 직접 재검증해서 각각 판정**했다.

| # | 구멍 | 어떻게 됐나 | 출처 |
|---|---|---|---|
| 1 | `_BalrogHeartService == nil` 이면 검증·차감을 **둘 다 건너뛰고 공짜 출발** | 없으면 **거절**로 반전 | A·B 공통 |
| 2 | 차감 뒤 `_MatchSessionLogic == nil` 이면 **심장만 사라지고** 매치는 없다 | **차감 전으로** 검사를 옮김 | A·B 공통 |
| 3 | `_PlayerDBManager == nil` 이어도 차감 성공 처리 → 다음 접속에 **심장이 되살아난다** | 창구 없으면 `false` | **B 단독** |
| 4 | 시계 역행 시 `at` 을 `now` 로 되감아, 복구될 때 **되감은 폭만큼 무료 스택이 공짜로** 들어온다 | `at` 유지 · 한 주기 초과만 재기준 | **A 단독** |
| 5 | 로드 전 기본값(0)을 실제 잔액처럼 심사 | 전원 `IsLoaded` 전엔 "불러오는 중" 으로 보류 | A·B 공통 |
| 6 | 원장 쓰기가 `CanWrite` 에 막혀도 `Charge` 가 **`true` 를 돌려준다** | 되읽어 **실제로 빠졌는지 확인** | 내가 찾음 |

#### 4번이 왜 재화 생성인가 (A 만 잡았고 B 는 `C. OK` 라고 했다)

`at` = 사이클 시작, 마감 = `at + 주기`.

- `at = 1000` · 주기 `100` → 마감 `1100`
- 시계가 `now = 500` 으로 되감김
- **옛 코드**: `at = 500` → 마감 `600`. 시계가 실제 `1000` 으로 복구되면
  `now - at = 500` → `gained = 5` → **무료 스택이 즉시 꽉 찬다**
- **고친 코드**: `at = 1000` 유지 → 마감 `1100`. 시계가 따라잡을 때까지 충전이 멈춘다

되돌아간 폭이 **한 주기를 넘으면** 일시 보정이 아니라 진짜 시각 리셋이라 보고 `now` 로 다시 잡는다.
이 방향은 마감이 **뒤로** 밀리므로 절대 공짜로 주지 않는다.

#### 6번 — `Charge` 가 자기 쓰기를 확인하지 않았다

`AddBalrogHeart` · `SpendFreeHeart` 는 둘 다 `CanWrite` 를 지나는데, 로드 전이면
경고만 찍고 **조용히 버린다**(반환값 없음). `Charge` 는 그걸 안 보고 `true` 를 돌려줬다.
결과: **아무도 안 냈는데 매치가 출발한다.**

이제 유저마다 차감 전후 잔액을 되읽어 `기대 == 실제` 를 확인하고, 어긋나면 `log_error` + `false`.
무료 스택이 버려져도 그만큼이 심장으로 넘어오므로 **심장 확인 하나로 둘 다 잡힌다.**

**⚠️ 일부만 빠진 채 `false` 를 돌려주는 경우가 있다.** 환불 수단이 없으므로
**뺀 것은 반드시 저장까지 보낸다** — 안 보내면 원장과 디스크가 갈라진다.

### 기타 방어

- `FreeHeartRefillSec = 0` 이면 나눗셈이 `inf` 가 되므로 `periodMs <= 0` 조기 반환
- `Charge` 는 **전원 검증을 먼저 끝낸 뒤** 한 명씩 뺀다 (앞사람만 빠지고 안 출발하는 상태 방지)
- 꽉 찬 상태에서는 타이머를 `0` 으로 멈춘다. 안 멈추면 다음 소모 때 **밀린 충전이 한꺼번에** 들어온다
- `math.min(maxStack, ...)` 클램프 덕에 시계가 앞으로 크게 튀어도 상한을 넘지 않는다
