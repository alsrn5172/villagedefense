## 2026-09-29 — PR 보고서 규칙 추가 (사용자 지시)

PR 을 올릴 때마다 개발한 내용과 검증한 내용을 보고서로 남기게 했다. 공지: #40 comment 5888347682.

- **보고서는 두 곳에 남긴다** (`협업-규칙.md` §3-1-3 신설). PR 본문 설명은 지금까지 쓰던 그대로 쓰고,
  보고서 페이지(Claude Artifact)를 따로 만들어 그 링크를 본문 맨 위에 넣는다.
- **캡처 파일이 반드시 있어야 한다** — 사진 파일 또는 mp4 영상. 코드 · 데이터 · 맵 · UI 가 하나라도 바뀌면
  직접 돌려서 확인하고 찍는다. 사람이 직접 찍어도 되고 AI 가 MCP 로 찍어도 된다.
- **stacked PR 은 한 페이지 안에 같이 싣는다.** 조각 PR 과 통합 PR 본문에는 같은 페이지 링크를 넣는다.
- **기한은 Ready for review 전환 전.** Draft PR 을 여는 시점(§3-1-2)에는 없어도 된다.
- **페이지에 싣는 것** — 개발한 내용 · 기능마다 검증 한 줄(구현한 것 · 캡처 · 증거 · 기타) · 정적 검사 · 못 본 것.
  항목마다 어디까지 확인했는지(데이터만 / Play 로그 / 화면) 구분한다.
- **캡처 파일은 저장소에 커밋하지 않는다.** 페이지에 올리고 PR 에는 링크만 둔다.
- **리뷰 항목 추가** (`협업-규칙.md` §3-2 ⑦) — 보고서 페이지 링크가 본문 맨 위에 있는가.
- **에이전트용 안내** (`AGENTS.md` 프로젝트 오버라이드 O-6) — 정본 §3-1-3 을 가리키는 요약.
