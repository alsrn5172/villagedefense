판정 규약(`SetShapeFor`)은 `Shape.Position = pos + (OffsetX × facing, OffsetY)`, `Size = (RangeX, RangeY)`.
`BoxShape.Size` 는 반폭이 아니라 **전체 폭·높이**다.
스프라이트 기본 방향이 왼쪽이라(`PlayCastEffect` 가 `facing > 0` 일 때 `FlipX`) 원점 기준으로
**전방 = `pivotX/100`**, **후방 = `(W-pivotX)/100`**, **위 = `(H-pivotY)/100`**, **아래 = `-pivotY/100`**.
준비 동작과 `stand` 꼬리를 뺀 "실제로 뻗은 프레임"들의 합집합을 썼다.

### 확인 대기

## 2026-09-03 (7차) — 솟구침의 진짜 원인은 점프 중첩

### ⚠️ 6차의 전제가 취소됐다

6차는 **"세로 발판에 몸을 비비면 위로 밀려 올라간다"** 는 사용자의 예전 관찰을 전제로 삼았다.
사용자가 이를 **철회**했다 — 그건 그냥 벽이 비스듬히 그어져 있어서였다.

→ 그 전제로 넣은 `RigidbodyComponent.IsBlockVerticalLine = true` 를 **되돌렸다.**
근거 없는 물리 설정은 변수만 늘린다.

### 확정된 사실

사용자 확인: **"안전망은 거침. 다시 복귀는 하더라. 근데 위로 점프 오지게 뜀."**

안전망이 걸렸다 = 보스가 실제로 높이 올라갔다. 그리고 원인은 **점프 중첩**이다.
엔진이 밀어 올린 게 아니라 `movement:Jump()` 가 반복해서 나갔다.

### 왜 중첩됐나

| 방어선 | 왜 안 통했나 |
|---|---|
| `IsOnGround() == false` 면 return | **상승 중에도 참이 돌아오는 순간이 있다** |
| `RealMoveVelocity.y` 검사 | `LIA-1116` — 이 프로퍼티를 못 읽는 경우가 있어 `nil` 이면 통과해 버렸다 |
| 쿨다운 0.45초 | **체공이 0.45초보다 길다.** 착지 전에 다음 점프가 나가 속도가 누적된다 |

### 수정

**(1) 프레임 간 y 차이로 상승을 직접 잰다**

엔진 프로퍼티를 안 믿는다. `riseY = 이번 y - 지난 프레임 y` 를 `StateTypeChase.OnUpdate` 에서
매 프레임 계산해 넘기고, `riseY > 0.005` 면 점프를 건너뛴다. `nil` 이 나올 여지가 없다.

**(2) 점프 쿨다운 0.45 → 1.0초**

체공 시간보다 길게 잡아, 착지 전에 다음 점프가 나갈 수 없게 한다.

**(3) 🔴 안전망의 복귀 지점이 (0,0) 일 수 있었다**

`homeX/homeY` 를 `OnBeginPlay` 에서 잡았는데, **스포너가 위치를 넣기 전에 `OnBeginPlay` 가
돌면 (0,0) 이 박힌다.** 그러면 복귀가 오히려 보스를 맵 위 허공으로 쏘아 올린다.
(이번엔 우연히 제대로 돌아왔지만 언제든 터질 수 있었다)

→ **"마지막으로 땅을 밟고 있던 자리"** 를 매 프레임 갱신해 그걸 복귀점으로 쓴다.
`homeSet` 이 서기 전에는 안전망을 아예 돌리지 않는다.
판정도 `공중 3초 AND 높이 6` 에서 **높이 6 하나**로 바꿨다 — 공중 판정을 신뢰할 수 없기 때문.

### 임시 계측 (원인 확정 후 제거할 것)

- `[FlyAway] JUMP <이름> y= rise= edge= blocked= tries=` — 점프가 나갈 때마다
- `[FlyAway] <이름> up= y= onGround= vel= state= jumpCd=` — 지면보다 1.5 이상 뜬 동안 0.5초마다

`maker_logs(kind="normal")` 로 읽는다. 점프가 몇 번 · 어떤 트리거로 나가는지 확정되면 지운다.

## 2026-09-03 (6차) — 🔴 보스가 하늘로 솟구쳐 날아간 사고

### 증상

스텀피가 이동속도 증가 버프를 켠 직후 하늘로 솟구쳐 사라졌다.

### 원인 — 내가 4차·5차에 넣은 두 기능이 기존 엔진 동작과 겹쳤다

사용자가 예전에 이미 관측한 엔진 동작이 있다:

> "foothold를 세로로 세워서 해결했음 근데 몸 갖다 박고 비비면 위로 상승하네 뭔 버그냐"

**세로 발판에 몸을 비비면 엔티티가 위로 밀려 올라간다.** 여기에 두 가지가 겹쳤다:

1. **이동속도 버프 ×1.5** → 벽을 더 세게 민다 → 더 빨리 밀려 올라간다
2. **4차의 정체 감지 점프** → 벽에 막히면 정체로 판정해 계속 뛴다 → 벽타기가 무한 반복

게다가 밀려 올라가는 도중 `IsOnGround()` 가 참으로 돌아오는 순간이 있어
**공중에서 점프가 겹쳐 쌓였다.** 이게 "솟구쳐 날아간" 직접 원인이다.

### 수정 — 원인 3중 차단 + 안전망

**(1) 상승 중에는 절대 안 뛴다**

`RigidbodyComponent.RealMoveVelocity.y` 의 절대값이 0.1 을 넘으면 점프를 건너뛴다.
`IsOnGround()` 만 믿으면 밀려 올라가는 중에도 참이 나온다.

**(2) 정체 트리거에 높이 조건을 되살렸다**

- 발판 끝 트리거 (`PredictFootholdEnd`) — 높이 안 본다(사용자 확정 유지)
- **정체 트리거 — 대상이 0.3 이상 위에 있을 때만**

정체는 "턱을 못 넘는 것"과 "벽에 막힌 것"을 구분하지 못한다. 대상이 위에 없으면
벽에 막힌 것이므로 뛸 이유가 없다.

**(3) 헛점프 누적 차단**

뛰었는데도 x 가 안 늘면 벽이다. **4번 헛뛰면 3초간 점프 금지.**
x 가 실제로 늘면 카운터를 지운다.

**(4) `RigidbodyComponent.IsBlockVerticalLine = true`**

`Foothold.isBlockVertical` 만 켜는 걸로는 부족했다. **부딪히는 쪽 엔티티의
`RigidbodyComponent.IsBlockVerticalLine` 도 true 여야 "막힌다".**
false 면 깔끔히 막히는 대신 밀려 올라가 벽을 탄다.
