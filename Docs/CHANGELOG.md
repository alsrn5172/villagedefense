## 2026-09-02 (4차) — 피아누스 B 폐기 + 피아누스가 보스로 동작하지 않던 문제

### 피아누스 B(`8520000`) 폐기 — 이 게임에서는 동굴 오른쪽 하나만 (사용자 확정)

원본은 **피아누스의 동굴에 좌·우 한 쌍**으로 박혀 있다. 리소스 조사 결과:

- 스프라이트(416×364, pivot `217,28`) · 클립 구성 · 등장 맵 5곳이 **완전히 동일**
- 차이는 **이펙트 좌우 반전**뿐 (`8510000` attack1 이펙트 pivot `(260,46)` = 왼쪽 / `8520000` `(-8,39)` = 오른쪽)
- 우열은 리소스로 안 갈린다 — `mobname`/`path` 는 `8510000` 이 상위(변종들이 그 자산을 재사용),
  `tags`/`description` 은 `8520000` 에 `boss` 가 붙는다. 신호가 반대로 간다

지운 것 — `BossInfo` 1행 · `BossSkills` 7행 · `MapMonsters` 배치 1행 · `MonsterInfo` 도감 1행 · 모델 파일 1개.

남은 피아누스는 이름 `피아누스 (Pianus)`, 좌표 **`(5.68, -1.33)` 오른쪽 고정**.
원래 `MapMonsters` 에 좌우 2행이 박혀 있었는데 **배치 행도 지우고 발록·마노처럼 `BossSpawner` 가 좌표로 스폰**하게 했다.
그대로 뒀으면 이중 스폰이다.

### 🔴 피아누스는 보스로 동작한 적이 없었다

두 가지가 겹쳐 `BossSkills` 7행이 통째로 죽은 데이터였다.

1. **모델에 `script.BossSkillRunner` 가 없었다.** `script.MonsterAttack` 이 그대로였다 —
   보스 6종만 교체했고 피아누스 2종은 빠져 있었다. 즉 일반 몹으로 뜨고 있었다.
   교체 + `StateChaseMonster.IsLegacy=false` + `ActionSheet` 를 넣었다.
   팩에 `move` 클립이 없어(벽에 박힌 정지형) `move`/`chase` 는 `stand` 로 매핑했다.
2. **`IsChaseNearPlayer = false`** 라 추격 대상을 영원히 못 잡는다.
   `DistanceToTarget` 이 항상 `99999` 를 줘서 **사거리 판정이 무조건 실패**한다.
   `GetChaseTarget` 에 최근접 플레이어 직접 탐색 폴백을 넣었다.
   대상이 없을 때만 돌고, 사거리 제한은 `SkillReach` 가 그대로 건다.

### 확인 대기

- 피아누스 `HitComponent` 에 `BoxSize`/`ColliderOffset` 이 없다(발록은 `0.67×1.42`).
  스프라이트가 416×364 로 큰데 판정 박스가 기본값이라 때리기 어렵거나 엉뚱한 데서 맞을 수 있다
- 이펙트가 좌우 반전 자산이라 `PlayCastEffect` 의 `FlipX` 규칙이 반대로 걸릴 수 있다

머쉬맘 S1(32×44) · 킹슬라임 S1(208×128) · 피아누스 A/B 각 S1(244×316)·S2(292×292)·S3(336×404).

발록 S3 만 `1.8, 1.1` 인데 그건 원본 위치가 몸통에 겹쳐 안 보인다는 지적을 받아 밖으로 뺀 예외다.

### 소환 5종 (`summon`)

마노←달팽이(`100000`) · 머쉬맘←주황버섯(`1210102`) · 킹슬라임←슬라임(`210100`) ·
스텀피←스텀프(`130100`) · 에피네아←페어리(`3000001`). 피아누스는 없음(사용자 확정).

`MonsterCatalog` 폴백을 넣었다. `MonsterInfo` 에는 `attackPower`·사운드 칸이 없으므로 있는 것만 넣는다.

쿨 30 · HP 0~60% · 3마리 · 폭 2.5 는 **튜닝용 자리표시자**다.

### ⚠️ ShapeType 8행 재배정 — 미검증

이펙트/명중 스프라이트 **실측 크기**로 배정했다. 규칙:

| 조건 | 배정 |
|---|---|
| 하위요소 없음 | 손대지 않는다(근거 없음) — 13행 |
| 폭 < 1.2 | `target` |
| 폭 ≥ 1.2, 높이/폭 ≥ 1.2 (세로로 김) | `crouchable` 머리 위 → 숙여 회피 |
| 폭 ≥ 1.2, 높이/폭 ≤ 0.8 (가로로 납작) | `ground` 지면 → 점프 회피 |
| 그 외 | `box` |

킹슬라임 S1 `target`→`ground` · 에피네아 S2 `box`→`target` · S3 `ground`→`target` · S4 `target`→`box` ·
피아누스 A/B S1 `target`→`crouchable` · S3 `ground`→`crouchable`.

🔴 **크기 추정도 결국 추정이다.** 해당 행 `#Note` 앞에 `⚠️미검증` 을 붙였다.
애니메이션을 직접 보고 확정할 때 그 표시를 지운다.
`ground`/`crouchable` 은 애니메이션이 아니라 **설계 선택**이라 데이터로는 못 정한다.

### 확인 순서 (사용자 지정)

킹슬라임 → 머쉬맘 → 스텀피 → 마노 → 에피네아 → 피아누스

## 2026-09-02 (2차) — 진영 체계 전면 도입 + 보스 연출(사운드·이펙트) + 발록 패턴 3종

### 🔴 플레이어가 야생 몹·보스를 **아무도 못 때리고 있었다**

`PlayerAttack.IsAttackTarget` 이 "파밍 몹(`script.FarmReward`)이거나 `IsEnemy` 인 것"만 통과시켰다.
그런데 모델 110종 중 `script.Faction` 을 가진 건 **10종뿐**(미니언 7 · 터렛 2 · 중립 1)이고,
`Models/Monsters` 82종(일반 몹 76 + 보스 8)은 **하나도 없었다**.
→ `GetTeam` 이 전부 `Neutral` 을 주고 → `GetRelation` 이 `NEUTRAL` → **후보 목록에서 통째로 제외.**

진영 밖에 예외(`isFarm`)를 하나 두는 순간, 진영을 안 가진 엔티티는 조용히 공격 대상에서 사라진다.
그래서 예외를 없애고 **모든 엔티티가 진영을 갖도록** 바꿨다.

### 진영 번호 체계 (사용자 확정)

| 대역 | 뜻 |
|---|---|
| `1`~`5` | 플레이어 **캐릭터만** |
| `11`~`15` | 미니언. `11` = 플레이어 1 을 치러 온 미니언 |
| `21`~`25` | 방어시설·자기 유닛. `21` = 플레이어 1 의 터렛·수비 |
| `Monster` | 야생 몹 · 보스 · 파밍 몹 공통 |
| `Neutral` | 그 외. 공격도 버프도 안 통한다 |

**소유자 = 번호 % 10.** 지정 대상은 별도 칸이 아니라 **팀 번호 자체**에 저장된다(`11` → 대상은 `1`).

관계 — 캐릭터끼리 `ALLY`(경쟁은 사냥 스틸로만) / **남의 방어시설은 `ENEMY`**(때릴 수 있다) /
미니언은 지정 대상의 것(`1`·`21`)만 적대하고 `2`~`5`·`22`~`25` 와는 아군 / 미니언끼리 아군 / `Monster` 는 전원과 적대.

같은 미니언이 상대에 따라 적/아군이 갈리므로 **팀 문자열 비교로는 표현이 안 된다.**
`FactionLogic.BandRelation` 특례가 일반 규칙(팀 다르면 적대)보다 먼저 적용된다.

`GetTeam` 3순위로 "`script.Monster` 또는 `script.FarmReward` 보유 → `Monster`" 를 넣어
**모델 82개를 고치지 않고 판정 한 곳에서** 해결했다.

⚠️ 기존 `TeamA` 는 `1` 이 아니라 **`21`** 로 간다. 그걸 달고 있던 건 캐릭터가 아니라 유닛·터렛이었다.
`NormalizeTeam` 이 흡수하므로 모델 10종은 그대로 뒀다. `FactionAuraController.PlayerTeam` 만 캐릭터 진영이라 `TeamA`→`1` 로 따로 받는다.

### 보스 사운드 — 8종 전부

원본 팩의 `_audio/*` 를 전부 배선했다. **여태 소리가 하나도 없었다.**

- `BossSkills.CastSoundRUID` 시전음(`_audio/AttackN`·`SkillN`) — 33행 중 25행
- `BossSkills.HitSoundRUID` 플레이어 피격음(`_audio/CharDamN`)
- `BossInfo.DamagedSoundRUID` / `DieSoundRUID` 보스 피격·사망음 — 8종 전부

`_SoundService` 는 `ClientOnly` 라 서버에서 그냥 부르면 대상이 모호하다.
`script.Monster.PlaySoundToMap` 이 맵 안 유저를 돌며 `targetUserId` 를 붙여 보낸다(SummonManager 와 같은 방식).
일반 몹 76종도 같은 통로를 쓰지만 기본값이 빈 문자열이라 동작은 그대로다.

### 🔴 이펙트 좌표를 판정 박스에서 분리

`CastEffectOffsetX` / `CastEffectOffsetY` / `CastEffectScale` 3열 신설.

원본 이펙트는 pivot 에 위치가 박혀 있는데 **기준이 자산마다 다르다.**
`attack2/info/effect` 는 `(-55,-57)` 로 손 높이 기준, `attack3/info/effect` 는 `(138,-27)` 로 몸통 기준이다.
판정 박스의 `OffsetX/Y` 를 재사용하면 두 번 밀려 허공에 뜨고, 반대로 오프셋을 빼면 몸통에 겹쳐 작아 보인다.
**하나의 규칙으로 못 맞춘다 — 자산별로 실측해서 넣는다.**

### 발록 패턴 — `fake` · `summon` 2종 신설

- **`fake`** 페이크 모션. 시전 모션·소리는 진짜와 같고 발사 순간 **판정을 아예 안 낸다.**
  `RecoverTime 0` 이라 발사 직전에 모션이 끊긴다. 이펙트는 전부 비워야 안 들킨다.
  `Priority` 를 진짜보다 낮게 둬 빈 구간만 채운다. `S2F`(쿨 29.1) · `S3F`(쿨 33.3), HP 70% 이하 전용
- **`summon`** 부하 소환. `ProjectileModelId`=모델 / `HitCount`=마리 수 / `RangeX`=좌우 폭.
  소환수 능력치는 `BossInfo` 를 그대로 쓴다 — 마노를 부르면 진짜 마노(HP 18,750)가 나온다.
  `RespawnOn=false` 로 세워 죽으면 사라진다(무한 증식 방지). `S4`, HP 5% 이하 · 쿨 9999 = 1회

사거리 처리도 갈랐다 — `summon` 은 거리 무관(추격 대상만 있으면), `fake` 는 흉내내는 진짜 스킬과 같은 거리.
안 갈랐으면 소환이 1.5 안에서만, S2 페이크가 9.0 대신 1.1 에서만 나갔다.

### 고친 버그

- **정지 시간이 고정 2초**였다. `CastDelay + RecoverTime` 이 2초를 넘으면 정지가 먼저 풀려
  **공격 자세인 채로 걸어다녔다.** 실제 시전 길이만큼 잡되 최소 2초는 보장한다
- **투사체가 항상 오른쪽을 봤다.** `BossProjectile.OnBeginPlay` 가 스폰 시점에 기본값 `DirectionX=1` 로
  방향을 고정하고, 호출부는 그 **뒤에** 값을 넣었다. 이동만 맞고 그림은 안 돌았다 → `SetDirection()` 신설
- **사거리 계산이 과했다.** 박스 바깥 끝은 `OffsetX + RangeX/2` 인데 `OffsetX + RangeX` 로 잡아
  안 닿는 거리에서도 시전했다. 발록 S3 `5.0`→`3.4`
- **피아누스 A/B 의 `CastRUID` 14행이 전부 비어** 있었다. 팩에서 찾아 채웠다(시전 모션 미검증)
- 발록 이동속도 `0.84`→`0.588`

### 확인 대기

- 피아누스 A/B 는 스폰 로그에 안 나온다(`SpawnX` 비움 = 기존 배치). **한 번도 못 봤다**
- 나머지 7종의 `ShapeType` 은 클립 순서·`ball` 유무로 **추정**한 값이다.
  발록에서 이 추정이 틀린 전례가 있다(`attack2` 를 "손톱긁기"로 적었는데 실제로는 날개 펼치기였다)
- 시전음 7행 누락 — 에피네아 `skillAfter3`, 피아누스 `attack3`·`skill1~3`. 원본 팩에 대응 사운드가 없다
- `AttackPower` / `Damage` 는 여전히 튜닝 대상 — `LevelTable` 이 자리표시자다

  수비대가 약하면 본인이 방어에 묶여 파밍을 못 하고, 그 시간 손실이 곧 도태다.
  "남을 공격한다" = "남의 시간을 뺏는다".
- **보스 판정** — 최다 누적 피해자가 처치 판정을 받고 획득 아이템을 **전부 독식**.
- **승패를 M1으로 승격** — 시설 3종 전파 상태에서 웨이브를 또 못 막으면 **함락 → 즉시 로비 퇴장**,
  **최후 1인 승리**. 종료 조건이 없으면 한 판이 끝나지 않아 게임으로 성립하지 않는다.
- **인원 2~6인 가변** — 빈 마을은 서버가 방어만 담당(승패 판정·파병 대상 제외).
  6인 고정은 실플레이 검증을 불가능하게 만들어 M1 완료 판정이 무한 연기된다.
- **K/D 필드 삭제** — 직접 PvP가 없는 구조라 항상 0인 필드를 두지 않는다.
- 마을 건물 HP는 **현행 유지** — 마을은 NPC만, HP를 가진 건 수비 시설 3종뿐.
  마을에는 플레이어 간 적대 행위를 차단하는 **억제 포탑**이 있다(공략 대상 아님).

### 공격 시스템 — 다중공격을 "가장 가까운 1마리만"으로

`AttackComponent` 는 범위 안 모든 대상을 때리므로, **2패스(probe → melee)** 로 바꿨다.
1패스에서 `IsAttackTarget` 이 후보만 수집하고 `false` 를 리턴해 아무도 안 맞게 한 뒤,
가장 가까운 하나를 골라 2패스에서 그 대상만 `true` 를 준다. (`PlayerAttack.mlua`)
