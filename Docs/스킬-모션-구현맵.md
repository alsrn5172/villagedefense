# 스킬 · 공격 모션 구현맵

> **스킬을 구현하기 전에 이 문서를 읽는다.** 어디에 뭐가 있고, 무엇이 검증됐고, 무엇을 하면 되는지가 여기 있다.
> 담당: 재생 계층·표 = **A** / 스킬이 어떤 무기에서 어떤 모션인지 = **B**
> 최초 작성 2026-09-08 (`a/item-equip-costume`)

---

## 0. 왜 이 문서가 생겼나

**증상**: 활을 장착하고 공격해도 활 쏘는 모션이 아니라 검 휘두르는 모션이 나갔다.

**추적 결과 (런타임 확인 완료)**:

| 확인한 것 | 결과 |
|---|---|
| `ItemInfo.AvatarSlot` 로드 | `TWO_HAND` ✔ |
| `_ItemCatalog:IsTwoHand("WEAPON_ARCHER_T10")` | `true` ✔ |
| 런타임 `CostumeManagerComponent` | `CustomTwoHandedWeaponEquip = 89836b97…`(활), `1H=[]`, `SUB=[]` ✔ |
| `AvatarStateAnimationComponent.IsLegacy` | `false`(엔진 기본 매핑) ✔ |
| `shoot1` 을 body 엔티티에 직접 전송 | **활 자세 정상 재생** ✔ |

**결론**: 장착은 완벽했다. 문제는 **MSW 가 무기를 끼웠다고 그 무기의 모션을 자동 재생해 주지 않는다**는 것이다.
엔진은 `ATTACK` 상태를 무기 카테고리로 풀지만 두손무기의 기본 해석은 **휘두르기(`swingT*`)** 라, 활은 활을 든 채 검처럼 휘두른다.
활 쏘기(`shoot1`), 아대 던지기 같은 모션은 **스크립트가 명시적으로 재생해야 한다.**

> ⚠️ 흔한 오해: "아바타 아이템 카테고리(`weapon` / `twohandweapon`)만 맞추면 모션이 따라온다".
> **아니다.** 카테고리는 필요조건일 뿐이다. 카테고리가 틀리면 손에 무기가 이상하게 들리고, 카테고리가 맞아도 모션은 따로 재생해야 한다.

## 2. B 가 하면 되는 것

### (1) 표에 행을 추가한다 — `WeaponMotion.csv`

```
MotionId,SkillId,WeaponType,CoreAction,PartsAction,PlayRate,PlayType,Enabled,#Note
```

- `SkillId` **빈칸 = 그 무기의 기본 공격 모션**. 값이 있으면 그 스킬 전용
- 조회 순서: `SkillId+WeaponType` 정확히 일치 → 없으면 `WeaponType` 기본 행 → 그것도 없으면 **아무것도 재생하지 않고 경고 로그**
- `PlayType` = `Onetime`(기본) / `Loop` / `ZigzagLoop`
- `PartsAction` 을 비우면 `CoreAction` 과 같은 값으로 채워진다

예) 궁수 스킬 `SKILL_POWER_SHOT` 을 활에서 다른 모션으로:

```
MOTION_POWER_SHOT,SKILL_POWER_SHOT,BOW,shoot2,shoot2,1.2,Onetime,true,파워샷
```

### (2) 스킬 발동 시 호출한다

```lua
-- 서버 스킬 로직 안에서
_PlayerMotion:PlaySkill(userId, "SKILL_POWER_SHOT")

-- 기본 공격이면
_PlayerMotion:PlayAttack(userId)
```

`PlaySkill` 은 **장착 무기를 스스로 조회**하므로 무기 종류를 넘길 필요가 없다.
클라이언트 재생까지 내부에서 처리한다(`@ExecSpace("Client")` 로 그 유저에게만 간다).

### (3) 공격 파이프라인을 새로 만들면

`PlayerAttack.mlua` `AttackNormal()` 첫 줄의 **⚠ 임시 배선**(모션 호출)을 새 파이프라인으로 옮기면 된다.
그 한 줄이 없어지면 활은 다시 검처럼 휘두른다.

## 3. 검증 상태 — 무엇이 확인됐고 무엇이 아닌가

| 항목 | 상태 |
|---|---|
| 활 RUID 가 두손 슬롯에 들어간다 | ✅ 런타임 확인 (2026-09-08) |
| `shoot1` 을 보내면 활 자세가 나온다 | ✅ 런타임 확인 (눈으로) |
| `WeaponMotion` 표 로드 → `PlayAttack` 로 활 모션 | 🟡 **미검증** (Maker 를 닫은 뒤 작성) |
| `swingT1`(두손검) · `stabO1`(단검) · `swingO3`(아대) · `swingO1`(너클/완드) | 🟡 **미검증 · 문서 후보값** — 눈으로 보고 조정 필요 |

**액션 이름은 추측하지 말 것.** 위 후보값은 `msw-avatar` 문서의 무기별 후보 목록에서 가져온 것이지 이 월드에서 확인한 값이 아니다.
확인 방법: Play 중에 아래를 클라이언트 컨텍스트로 실행하고 캐릭터를 본다.

```lua
local body = _UserService.LocalPlayer.AvatarRendererComponent:GetBodyEntity()
local ev = ActionStateChangedEvent()
ev.CoreActionName = "shoot1"   -- 바꿔가며 확인
ev.PartsActionName = ev.CoreActionName
ev.PlayType = SpriteAnimClipPlayType.Loop
body:SendEvent(ev)
```

## 4. 조용히 실패하는 지점

- **`ActionStateChangedEvent` 는 body 엔티티에 보내야 한다.** `AvatarRendererComponent:GetBodyEntity()` 로 얻는다.
  루트 엔티티(`self.Entity`)에 보내면 **에러 없이 아무 일도 안 일어난다**
- **`PartsActionName` 을 비우면** 상체만 움직이고 무기·모자 같은 파츠가 멈춘다
- **`PlayType` 기본값은 `Loop`** 다. 한 번만 재생할 액션은 `Onetime` 을 명시한다
- **ATTACK 자동 재생과 충돌**: 엔진이 `ATTACK` 상태 동안 매핑된 모션을 계속 밀어넣기 때문에, 커스텀 모션이 한 프레임 뒤 덮일 수 있다.
  그럴 땐 서버에서 `AvatarStateAnimationComponent:RemoveActionSheet("ATTACK")` 로 매핑을 걷어내고 전부 직접 재생해야 한다
  (`StateToAvatarBodyActionSheet` 은 `@Sync` 라 **서버에서** 불러야 한다). 현재는 걷어내지 않았다 — 필요해지면 그때 켠다
- **`ItemInfo.Enabled` 는 아무도 읽지 않는다.** 아이템을 목록에서 빼려면 `CraftRecipe.Enabled` 를 끈다
