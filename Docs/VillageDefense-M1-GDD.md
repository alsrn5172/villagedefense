## 1. 한 줄 콘셉트

**1레벨로 시작해 10레벨 전직과 함께 마을 하나를 차지하고, 무너지지 않으면서 슬리피우드의 주니어 발록을 가장 먼저 잡는 사람이 이긴다.** 마을로 향하는 사냥터 레인을 미니언이 끝없이 걸어오고, 그 사냥터가 곧 내 성장터이자 방어선이다. **20~25분짜리 성장 레이스형 마을 방어 게임.**

### 플레이어 판타지

- 처음엔 아무것도 없다. 사냥해서 **10레벨 전직**을 하고 나서야 마을 하나의 영주가 된다.
- 내 사냥터는 동시에 **내 방어선**이다. 발판 위에서 사냥하는 동안, 발밑 1자 길로 미니언이 마을을 향해 걸어간다.
- 포탑이 미니언을 막아주는 동안 나는 사냥한다. 포탑이 무너지면 전선이 마을 쪽으로 한 칸 밀린다.
- **억제기까지 부서지면 미니언이 더 강해진다 — 대신 주는 경험치도 오른다.** 위험과 보상이 같이 온다.
- 21레벨(3페이즈)부터는 남의 마을에 쳐들어가 그 사람의 코어를 직접 깰 수도 있다.
- 하지만 진짜 목표는 남이 아니라 **주니어 발록**이다. 버티면서 먼저 도달하는 것이 승리다.

### 핵심 재미 기둥

1. **사냥터가 곧 방어선** — 성장과 방어가 같은 공간에서 일어난다. 어디서 사냥할지가 곧 어디를 지킬지다.
2. **밀리는 전선** — 1차포탑 → 2차포탑 → 억제기 → 코어. 한 번에 죽지 않고 **한 칸씩 밀린다.** 그 과정이 서사다.
3. **억제기의 역설** — 방어선이 뚫릴수록 경험치가 오른다. 일부러 내주고 파밍할 것인가?
4. **레이스** — 남을 무너뜨리는 게 목표가 아니다. **발록에 먼저 닿는 것**이 목표다. 견제는 수단일 뿐.
5. **다가오는 시계** — 미니언은 시간에 따라 4단계로 강해지고, 25분이면 누구도 못 버틴다. 그전에 끝내야 한다.
6. **매치 성장과 계정 성장의 분리** — 한 판의 경제는 매번 초기화되지만 도감·업적·계정 성장은 남는다.

## 2. 게임 전체 그림 — 무엇이 무엇인가

> 이 절은 "마을이 뭐고 수비대가 뭐고 미니언이 뭐고 한 판이 어떻게 굴러가는가"를 한 번에 읽기 위한 사전이다. 세부 수치·계약은 §4 이후에 있다.

### 2.2 한 판의 흐름

전체 20~25분. **페이즈 전환은 매치 경과 시간으로 판정한다.** 아래 레벨은 "그 시각이면 이 정도 레벨일 것"이라는 **설계 기대치**이지 전환 조건이 아니다 — 개인 레벨로 페이즈가 갈리면 일부러 안 크는 버티기 전략이 생긴다.

```
로비 (2~6인 모임)
   ↓  매치 시작 — 전원 1레벨, 마을 없음, 수비대 없음
┌────────────────────────────────────────────────────┐
│  [1페이즈 — 개척]        기대 ~10레벨               │
│  미니언이 아직 나오지 않는다.                        │
│  사냥터에서 사냥해 10레벨 전직을 향해 달린다.         │
│  리스항구(Lv1~5 달팽이·스포아)가 이 구간의 무대다.    │
│  마노를 먼저 잡으면 10렙제 체력 갑옷을 독식한다.      │
├────────────────────────────────────────────────────┤
│  [2페이즈 — 마을]        기대 10~16레벨              │
│  10레벨 전직 → 마을 코어 연결 → 영주가 된다 (선착순)  │
│  → 포탑·모집·훈련·기능 NPC 10종이 이때 열린다         │
│  미니언 등장: 체력은 좀 있으나 공격력이 낮다.         │
│  → 방어선을 세우고 파밍 리듬을 잡는 구간              │
├────────────────────────────────────────────────────┤
│  [2.5페이즈 — 압박]      기대 16~21레벨              │
│  미니언 체력은 그대로, 공격력이 크게 오른다.          │
│  → 포탑이 실제로 깎이기 시작한다                      │
│  → 엘리트 몬스터 재료로 성장에 투자하는 구간          │
├────────────────────────────────────────────────────┤
│  [3페이즈 — 종막]        기대 21레벨~                │
│  미니언이 체력·공격력 모두 크게 오른다.               │
│  → 전선이 1차 → 2차 → 억제기로 밀린다                │
│  → 21레벨부터 남의 마을 침범이 가능해진다             │
│  → 슬리피우드 주니어 발록에 도전할 수 있게 된다        │
└────────────────────────────────────────────────────┘
   ↓  25분경이면 미니언이 감당 불가로 세져 방어선이 반드시 무너진다
주니어 발록을 먼저 잡은 사람 = 승리 → 계정 보상 정산 → 매치 데이터 폐기
```

한 판 안에서 플레이어가 반복하는 루프:

`레인 상태 확인 → 사냥·엘리트·보스로 자원 확보 → 제작·훈련·포탑 투자 → 밀리는 전선 방어(또는 내주고 파밍) → 남에게 파병 → 다시 사냥 → 발록 도전`

### 2.3 승패

- **승리**: **주니어 발록을 가장 먼저 잡는다.** 단 그때까지 자기 코어가 살아 있어야 한다.
- **패배**: **마을 코어가 파괴되면** 게임 오버. 코어에 닿으려면 §4.7의 4단 방어선(1차포탑 → 2차포탑 → 억제기 → 코어)을 순서대로 걷어내야 한다.
- **자연 종료**: 아무도 발록을 못 잡아도 판은 끝난다. 미니언이 무한히 강해져 **25분경이면 어떤 방어선도 반드시 무너진다.** 별도의 제한 시간 타이머를 두지 않는다 — 난이도 곡선 자체가 타이머다.
- 아직 10레벨을 못 찍어 마을이 없는 플레이어의 처리는 **미정**이다 (→ 로드맵 미정 #3).
- 인원이 6명 미만이면 남는 마을은 **주인 없는 빈 마을**로 남는다. 코어가 연결되지 않았으므로 미니언·파병 대상이 아니다.

### 2.4 왜 남을 공격하는가 — 이 게임의 경제

승리는 **발록에 먼저 닿는 것**이다. 그러므로 모든 경쟁은 **누가 더 빨리 성장하느냐**로 환원되고, 남을 공격한다는 것은 **그 사람의 성장 속도를 늦추는 것**이다.

1. 사냥터 몬스터는 **모두가 공유**한다. 리젠은 정해져 있고, 나와 있는 사람이 가져간다.
2. 내 포탑이 튼튼하면 미니언은 알아서 막힌다 → 나는 그 시간에 사냥에 집중할 수 있다.
3. 내 포탑이 약하면 **내가 직접 밧줄을 타고 내려가 미니언과 싸워야 한다.** 그 시간만큼 사냥을 못 한다.
4. 남들은 그 사이 레벨과 재료를 벌어들인다. **발록까지의 거리가 벌어진다.**
5. 그래서 나는 남의 레인에 **파병**을 보낸다. 그 사람의 전선이 밀리면 그 사람이 방어에 묶인다.
6. 묶인 사람은 투자도 못 한다 → 전선이 더 밀린다 → **발록 레이스에서 뒤처진다.**

#### 억제기의 역설 — 일부러 내줄 수도 있다

억제기가 부서지면 **미니언이 강해지지만 주는 경험치도 오른다.** 즉 방어선을 내주는 것이 순수한 손해가 아니다.

> 화력이 충분한 사람은 **일부러 억제기를 포기하고** 강해진 미니언을 사냥해 경험치를 벌 수 있다. 대신 다음 관문이 코어뿐이라 실수하면 즉사다. 이 도박이 후반 판단의 핵심이 된다.

> ⚠️ 초반 몰빵 공격은 성립하지 않는다. 파병에 자원을 쓰면 내 성장이 멈추고, 3페이즈 미니언에 내가 먼저 무너진다. **공격은 내가 충분히 앞선 뒤에 쓰는 견제 수단**이지 승리 수단이 아니다.

### 기준 화면과 좌표

- M1 기준 화면은 PC 16:9, 월드 기준 약 `12.8 × 7.2` 단위를 사용한다.
- MSW 월드 좌표는 `1 단위 = 100px`이므로 픽셀 값을 Transform에 직접 넣지 않는다.

## 4. 핵심 시스템 명세

### 4.1 마을과 방어 레인

> ⛔ **전용 수비 맵 6개는 만들지 않는다.** 안농의 포탈망이 **이미 이 구조 그대로** 깔려 있다 — 마을마다 `여섯갈래길 → 사냥터2 → 사냥터1 → 마을` 침공 레인과 `마을 → 사냥터3 → 보스맵` 후방 지선이 대칭으로 존재한다(2026-08-28 `PortalRoutes.csv` 실측). 신규 맵 제작 없이 기존 사냥터에 **하단 1자 길 + 밧줄 + 포탑**만 추가하면 된다.

| VillageId | 마을 맵 | 사냥터2 (1차포탑) | 사냥터1 (2차포탑·억제기) | 후방 지선 | 보스맵 |
|---|---|---|---|---|---|
| `ELLINIA` | `Ellinia_Village_MinimiMain` | `Ellinia_Hunt_TreeTrunkNest2` | `Ellinia_Hunt_GreenTreeTrunk` | `Ellinia_Hunt_GiantTree` | `Ellinia_Boss_Ephenia` |
| `HENESYS` | `Henesys_Village_MinimiMain` | `Henesys_Hunt_GolemsTemple` | `Henesys_Hunt_HillNorth` | `Henesys_Hunt_BlueMushroomTrail` | `Henesys_Boss_Mushmom` |
| `KERNING` | `KerningCity_Village_MinimiMain` | `KerningCity_Hunt_SubwayLine1` | `KerningCity_Hunt_ConstructionSite` | `KerningCity_Hunt_SewerApproach` | `KerningCity_Boss_KingSlime` |
| `PERION` | `Perion_Village_MinimiMain` | `Perion_Hunt_NorthernRidge` | `Perion_Hunt_WildBoarLand` | `Perion_Hunt_SouthernRidge` | `Perion_Boss_Stumpy` |
| `NAUTILUS` | `Nautilus_Village_MinimiMain` | `Nautilus_Hunt_WayToBeach` | `Nautilus_Hunt_PigPasture` | `Nautilus_Village_MinimiShip` → `Nautilus_Hunt_RibbonPigBeach` | `Nautilus_Boss_Pianus` |

⚠️ **커닝시티만 레인이 4단이다** — `SubwayLine1 → Village_SubwayEntrance → ConstructionSite → 마을`. 중간에 `Village_SubwayEntrance`가 낀다. 이 맵에 포탑을 둘지 통과만 시킬지는 제작 시 결정한다.

#### 레인 요소 계약

침공 레인의 세 맵(사냥터2 · 사냥터1 · 마을)은 아래를 반드시 갖춰야 한다. 지형은 원본 그대로라 서로 다르지만 이 요소가 빠지면 전투가 성립하지 않는다.

| 요소 | 어디에 | 설명 |
|---|---|---|
| **하단 1자 길** | 사냥터2 · 사냥터1 · 마을 | 맵 아래쪽을 가로지르는 평평한 통로. 미니언 전용 이동 경로 |
| **밧줄/사다리** | 사냥터2 · 사냥터1 | 위 사냥 발판 ↔ 아래 미니언 길. **플레이어가 개입할 수 있는 유일한 접점** |
| **미니언 진입 지점** | 사냥터2의 여섯갈래길 쪽 끝 | |
| **레인 끝 트리거** | 각 맵의 마을쪽 끝 | 미니언이 닿으면 **다음 맵으로 전선이 넘어간다** |
| **1차포탑 슬롯** | 사냥터2의 마을쪽 끝 | |
| **2차포탑 슬롯 · 억제기 슬롯** | 사냥터1 | 억제기는 2차포탑 **뒤**(마을 쪽) |
| **코어** | 마을, 여섯갈래길 방향 포탈 옆 | 최종 목표물 |
| 수비 몬스터 배치 슬롯 | 사냥터2 · 사냥터1 하단 길 | 모집·훈련한 몬스터를 세우는 자리 |

- 각 맵의 슬롯 절대 좌표와 하단 길 x 범위는 제작 시 MapBuilder 실측으로 확정해 `LaneConfig`에 마을별로 기록한다.
- **난이도 편차는 지형이 아니라 데이터로 보정한다** — 레인이 짧은 마을은 포탑 수치나 미니언 진입 간격을 `LaneConfig`에서 조정한다.
- 포탑·억제기·코어는 **마을 코어 연결 시 런타임 생성**하고, 수비 몬스터는 모집할 때마다 배치한다.
- ⚠️ **하단 1자 길이 없는 맵은 발판을 새로 깔아야 한다.** 발판 저작은 MapBuilder 커버리지 밖이라 **Maker UI 작업**이다 (`msw-general` 함정노트 §1). 마을당 최소 3개 맵 × 6마을 = **18개 맵의 지형 작업**이 필요하다 — 이 마일스톤에서 가장 큰 물리 작업이다.

사냥터·보스 맵의 최종 ID는 Phase 0에서 안농의 33개 맵과 포탈망을 감사한 뒤 `MatchRouteConfig` allowlist에 고정한다. allowlist가 비어 있으면 테스트 재화로 Phase 2를 개발할 수는 있지만 M1 릴리스 완료로 판정하지 않는다.

### 4.2 미니언 — 이 게임의 시계

미니언은 서버가 소유하는 **상시 흐름**이다. 별도의 "전투 인스턴스"를 열지 않는다 — 미니언은 그냥 레인 하단 길을 계속 걸어오고, 포탑·수비 몬스터·플레이어가 그때그때 막는다. **전투 시작/종료라는 개념 자체가 없다.**

#### 4페이즈 곡선

| 페이즈 | 기대 레벨 | 미니언 HP | 미니언 공격력 | 플레이어가 하는 일 |
|---|---|---|---|---|
| **1페이즈 — 개척** | ~10 | **미니언 없음** | — | 사냥해서 10레벨 전직. 리스항구가 무대 |
| **2페이즈 — 마을** | 10~16 | 있음 | **낮음** | 마을 확보, 포탑 구축, 파밍 리듬 확보 |
| **2.5페이즈 — 압박** | 16~21 | 그대로 | **크게 상승** | 포탑이 실제로 깎이기 시작. 엘리트 재료로 투자 |
| **3페이즈 — 종막** | 21~ | **크게 상승** | **크게 상승** | 전선이 밀린다. 마을 침범 해금. 발록 도전 |

- **전환 조건은 매치 경과 시간이다.** 위 레벨은 설계 기대치일 뿐 조건이 아니다 — 개인 레벨 기준이면 "일부러 안 크고 약한 미니언만 상대하는" 버티기가 성립한다.
- 전환 시각·투입 간격·HP/공격력 배율은 전부 `MinionPhaseConfig` 데이터로 둔다. 코드에 넣지 않는다.
- 미니언 구성(종류·수량·레벨)은 `MinionComposition`에 페이즈별로 정의한다.
- 미니언은 안농 도감 77종에서 고른다. "어둠에 물든 파괴된 헤네시스·페리온의 몬스터"라는 설정에 맞는 종을 페이즈별로 배정한다.
- **25분경이면 곡선이 감당 불가 수준에 도달해 어떤 방어선도 무너진다.** 이것이 이 게임의 실질 제한 시간이며, 별도 타이머를 두지 않는다.

#### 전선 이동

미니언은 한 마리씩 계속 흘러온다. 전선은 다음 규칙으로만 움직인다.

```
[사냥터2] 1차포탑 생존 → 미니언은 여기서 막힌다
              ↓ 1차포탑 파괴
          미니언이 레인 끝에 닿음 → 전선이 사냥터1로 이동
[사냥터1] 2차포탑 → 파괴되면 그 뒤 억제기를 공격
              ↓ 억제기 파괴
          ⚡ 미니언 강화 + 미니언이 주는 경험치 소폭 상승
          미니언이 레인 끝에 닿음 → 전선이 마을로 이동
[마을]    코어 공격 → 코어 파괴 시 게임 오버
```

- **전선은 되돌아가지 않는다.** 포탑을 재건해도 미니언 진입 지점이 앞으로 돌아오지는 않는다 (⚠️ 재검토 대상 → 로드맵 미정 #9).
- 포탑·억제기 파괴는 **각각 1회성 이벤트**다. 같은 파괴를 두 번 반영하지 않는다.
- 플레이어 공격은 **3페이즈(21레벨) 전에는 포탑·억제기에 거의 데미지가 들어가지 않는다.** 초반 견제를 원천 차단하기 위한 의도된 저항값이다.

#### 미니언 처치 보상

- 미니언은 잡으면 **경험치와 메소**를 준다. 즉 **방어는 파밍이기도 하다.**
- **억제기가 부서지면 미니언이 주는 경험치가 소폭 오른다.** 방어선을 내주는 것이 순수한 손해가 아니게 만드는 장치다 (§2.4 억제기의 역설).
- 파병 몬스터는 처치해도 보상을 주지 않는다 — 보상을 주면 파병이 상대를 돕는 꼴이 된다.

### 4.3 파병 — 유일한 공격 수단

21레벨 전에는 상대를 직접 때릴 수 없다. 대신 자기 몬스터를 상대의 방어 레인으로 보낸다.

- 파병 접수는 `SixPathCrossway`의 **공용 파병 접수 NPC**에서 한다.
- 대상은 **주인이 있고 아직 살아 있는 다른 플레이어의 마을**이다. 주인 없는 빈 마을과 자기 마을은 대상이 될 수 없다.
- 보낸 몬스터는 **미니언 흐름에 합류**해 상대 레인을 함께 걸어간다. 별도의 전투 인스턴스를 만들지 않는다.
- 파병한 몬스터는 **내 보유 목록에서 즉시 빠지고 돌아오지 않는다.** 즉 파병은 **내 수비 전력을 깎아 남의 시간을 뺏는 거래**다.
- 파병 신청은 실제 투입 전까지 취소할 수 있고, 취소하면 몬스터가 보유 목록으로 돌아온다.
- 한 마을이 동시에 받을 수 있는 파병 총량에는 상한을 둔다(`DispatchCap`, 데이터).
- 방어자는 **"내 레인에 파병이 섞였다"는 사실과 총량 등급만** 통보받는다. 누가 보냈는지, 정확히 무엇을 보냈는지는 공개하지 않는다.

> 밍키타연습월드1에는 이미 파병 리모컨 UI(`style-4-blue` 메이플식 팝업)와 `RequestDispatchBatch` 계열 서버 검증 흐름이 있다. Phase 0에서 이 자산의 재사용 범위를 판단한다. ⚠️ `any` 타입은 ExecSpace를 넘지 못하므로 카트는 문자열 직렬화로 보낸다(기존 `[LEA-3036]` 사고).

### 4.4 방어자 직접 참전

- 레인이 곧 사냥터이므로 **밧줄로 내려가면 곧바로 미니언과 싸울 수 있다.** 언제든 가능하다.
- 진입하면 플레이어 캐릭터가 정상 전투 상태로 미니언과 싸운다. 무적·조작 잠금은 없다.
- 남의 레인에도 들어갈 수는 있다(사냥터이므로). 다만 **21레벨 전에는 그 사람의 포탑·억제기에 데미지가 거의 안 들어간다.**
- 참전 중에는 사냥터·보스룸에 갈 수 없다. **이 시간 손실이 게임의 핵심 압박이다.**
- 방어자가 사망하면 마을로 귀환한다. 코어 판정에는 영향을 주지 않는다.
- 수비 시설·수비 몬스터의 자동 전투는 방어자 참전 여부와 무관하게 항상 돌아간다.

### 4.5 공유 사냥터와 보스

- 사냥터 몬스터는 **아무도 소유하지 않는다.** 안농의 CSV 스포너(`MonsterSpawner`) 규칙을 그대로 쓴다.
- 리젠은 슬롯별 `RespawnSeconds`로 정해져 있고, 먼저 잡은 사람이 가져간다. 채널·인스턴스 분리는 하지 않는다.
- 보스룸은 걸어서 입장한다. **보스 처치 판정 = 누적 피해 최다 플레이어.** 그 사람이 획득 아이템을 전부 가져간다.
  - 누적 피해는 서버가 보스 엔티티에 `DamageLedger(userId → total)`로 기록한다.
  - 동률이면 마지막 타격자를 우선한다.
  - 처치 판정을 못 받은 참여자에게는 보상이 없다. 이것이 보스룸 눈치싸움을 만든다.
- 사냥·보스 보상은 전부 **매치 자원**이다. 계정 재화가 나오지 않는다.

#### 매치 자원 3종

| 자원 | 얻는 곳 | 쓰는 곳 |
|---|---|---|
| **경험치** | 사냥·보스·미니언 | 매치 레벨. **10레벨 전직이 마을 점유 자격선**이라 1페이즈의 유일한 목표다 |
| **메소** | 사냥·보스 | NPC 거래 전반 — 제작, 강화, 수리, 물약, 몬스터 구매, 훈련, 시설 강화·수리·재건 |
| **보석 12종** | 사냥·보스 (종류별 드롭처 분리) | **능력치별 업그레이드 재료** |

보석 12종과 대응 능력치:

| 보석 | 능력치 | 보석 | 능력치 |
|---|---|---|---|
| 다이아몬드 | 공격력 | 사파이어 | 마력 |
| 자수정 | 이동속도 | 아쿠아마린 | 점프력 |
| 가넷 | 명중률 | 오팔 | 회피율 |
| 토파즈 | HP | 에메랄드 | MP |
| 힘의 크리스탈 | STR | 민첩성의 크리스탈 | DEX |
| 행운의 크리스탈 | LUK | 지혜의 크리스탈 | INT |

- 보석은 `GemInfo` 데이터로 정의하고, 어떤 몬스터·보스가 어떤 보석을 떨구는지는 `GemDropTable`로 둔다.
- 🔴 **보석은 장비 강화에 쓴다** (2026-08-29 확정, 구 미정 #6 해소). **강화 장인(`WORKSHOP_ENHANCE`)** 에서 메소와 함께 소모하며, 보석 종류가 그 강화로 오르는 능력치를 결정한다 — 다이아몬드를 넣으면 공격력이, 토파즈를 넣으면 HP가 오른다.
- 따라서 **수비대·포탑 강화에는 보석을 쓰지 않는다.** 그쪽은 메소와 **엘리트 재료**가 담당해 두 축이 갈린다.
  - 플레이어 강화 축 = **메소 + 보석**
  - 방어 축 = **메소 + 엘리트 재료**
- 능력치 이름이 메이플 원본 스탯 체계(STR/DEX/LUK/INT, 공격력/마력, 명중/회피)를 그대로 쓰므로 장비에 붙는 스탯과 1:1로 대응한다.

### 4.6 NPC 역할 목록

‘공용 NPC’는 한 장소를 모든 플레이어가 공유한다는 뜻이 아니다. **역할별 모델·컴포넌트·UI를 재사용하되 각 마을에 소유권이 붙은 인스턴스를 둔다.**

| 구역 | NpcRole | 표시 역할 | 핵심 기능 | 변경하는 상태 |
|---|---|---|---|---|
| 공방 | `WORKSHOP_CRAFT` | 제작 장인 | 재료를 매치 장비·소모품으로 제작 | `MatchPlayerState` |
| 공방 | `WORKSHOP_ENHANCE` | 강화 장인 | 매치 장비 성능 강화 | `MatchPlayerState` |
| 공방 | `WORKSHOP_REPAIR` | 수리 장인 | 플레이어 매치 장비 내구도 복구 | `MatchPlayerState` |
| 공방 | `SHOP_POTION` | 물약 상인 | 매치 재화로 물약 구매 | `MatchPlayerState` |
| 생활 | `LIFE_STORAGE` | 창고지기 | 이번 매치 전용 재료·장비 보관 | `VillageMatchState` |

별도의 ‘플레이어 성장 훈련장 NPC’는 M1에 추가하지 않는다. 플레이어 성장은 사냥, 장비, 계정 해금으로 처리한다.

#### 공용 기능 NPC

공용 NPC는 플레이어 소유 마을의 내부 상태를 직접 편집하지 않는 기능으로 제한한다. 아래 인스턴스는 마을당 10개, 총 60개 계산에 포함하지 않는다.

| 위치 | NpcRole | 이용 범위 | 기능 |
|---|---|---|---|
| 로비 | `COMMON_MATCH_GUIDE` | 로비의 모든 플레이어 | 매칭 참가·취소, 준비 확인 상태, 규칙 안내 |
| `SixPathCrossway` | `COMMON_DISPATCH_OFFICER` | 같은 MatchId의 생존자 | 대상 선택, 공개 요약 확인, 파병 편성·취소, 현재 페이즈 안내 |

파병 접수 NPC는 대상의 시설·몬스터 상세를 공개하지 않으며, 실제 편성은 항상 `WaveService`의 서버 검증을 거친다.

#### NPC 접근 권한

모든 상호작용은 클라이언트 UI 오픈 여부와 무관하게 서버에서 다시 검사한다.

`CanUseVillageNpc(userId, npcInstanceKey)`의 통과 조건:

1. 현재 Room의 활성 `MatchId`가 존재한다.
2. 서버가 `npcInstanceKey`를 현재 존재하는 NPC 엔티티로 해석하고 그 엔티티에서 `MapName`, `VillageId`, `CatalogNpcId`를 역산한다.
3. 요청자의 `OwnerUserId`가 해당 `VillageId`의 소유자다.
4. 역산한 `CatalogNpcId`와 NPC 역할이 서버 `FunctionalNpcCatalog`에 등록돼 있다.
5. 요청자가 상호작용 거리와 호출 빈도 조건을 만족한다.
6. (상시 전투 구조이므로 "전투 중 잠금" 조건은 두지 않는다.)

실패 시 상태를 변경하지 않고 공통 토스트로 거절 이유를 알린다.

클라이언트가 보낸 `VillageId`, `OwnerUserId`, NPC 역할은 권한 판정에 사용하지 않는다. 런타임 키 형식은 서버가 생성한 `MatchId:VillageId:CatalogNpcId:SpawnOrdinal`이며, 클라이언트에는 불투명 문자열로 취급한다.

### 4.7 방어 시설과 패배

| 시설 | 위치 | 역할 | 성장 효과 | 피해 처리 |
|---|---|---|---|---|
| **1차포탑** | 사냥터2 마을쪽 끝 | 첫 관문. 미니언을 여기서 막는다 | 공격력, 공격 속도, 사거리, HP | 현재 HP 누적, 0이면 파괴 |
| **2차포탑** | 사냥터1 | 두 번째 관문 | 위와 동일 | 현재 HP 누적, 0이면 파괴 |
| **억제기** | 사냥터1, 2차포탑 뒤 | 마지막 관문. **부서지면 미니언 강화 + 경험치 상승** | 최대 HP, 방어력 | 현재 HP 누적, 0이면 파괴 |
| **코어** | 마을, 여섯갈래길 포탈 옆 | 패배 목표물 | HP만 | 0이면 **게임 오버** |

- 넷 다 **포탑 관리관 NPC 한 명**을 통해서만 강화·수리·재건한다.
- 파괴된 것은 자동 복원되지 않는다. 재건 비용을 지불해야 한다.
- **잠금 없음** — 상시 전투라 "전투 중 변경 금지" 구간이 존재하지 않는다. 대신 파괴된 시설의 재건에는 시간과 비용이 들어 즉시 복구는 불가능하다.
- ⚠️ **1차포탑은 3페이즈쯤 거의 반드시 부서지도록 설계한다.** 안 부서지면 전선이 안 밀리고 판이 끝나지 않는다.

#### 4단 방어선과 패배

마을은 한 번에 무너지지 않는다. **네 겹을 순서대로 잃어야** 게임 오버다.

```
[1차] 사냥터2 — 1차포탑
          │ 파괴 → 미니언이 레인 끝에 닿으면
          ▼
[2차] 사냥터1 — 2차포탑
          │ 파괴 → 그 뒤 억제기를 공격
          ▼
[3차] 사냥터1 — 억제기
          │ 파괴 → ⚡ 미니언 강화 + 미니언 경험치 소폭 상승
          │        미니언이 레인 끝에 닿으면
          ▼
[4차] 마을 — 코어
          │ 파괴
          ▼
       게임 오버
```

- **앞 관문이 살아 있는 한 뒤는 안전하다.** 한 번의 사고로 즉사하지 않는다.
- **21레벨(3페이즈) 전에는 플레이어 공격이 포탑·억제기에 거의 안 통한다.** 그래서 초반 견제로 남을 무너뜨릴 수 없다.
- **21레벨부터 남의 마을에 침범해 코어를 직접 공격할 수 있다.** 미니언이 억제기를 뚫었는지와 무관하다.
- 패배 처리는 서버가 원자적으로 수행한다: 활성 파병 취소 → 계정 보상 정산 → 매치 상태에서 제거 → 로비로 이동.
- 승자는 **주니어 발록을 먼저 잡은 사람**이다. 전원이 코어를 잃으면 승자 없이 종료된다.


### 4.8 몬스터 구매·훈련·회복

#### 구매

- 몬스터는 ‘병과 해금’이 아니라 **개별 개체**를 구매한다. 같은 종류를 여러 번 구매할 수 있다.
- 각 개체는 `MonsterInstanceId`, `MonsterTypeId`, `CurrentHp`, `Status`를 가진다.
- 전투에서 사망한 수비 몬스터 개체는 영구 사망 처리되어 매치 보유 목록에서 제거한다.
- 파병으로 내보낸 개체도 보유 목록에서 제거된다(§4.3).

#### 훈련

- 훈련 레벨은 개체가 아니라 `MonsterTypeId`별 **병과 레벨**이다.
- 이미 보유한 개체와 이후 구매할 개체에 같은 병과 훈련 보너스를 적용한다.
- 서로 다른 병과는 동시에 훈련할 수 있다. 같은 병과에는 동시에 하나의 훈련 작업만 존재한다.
- M1에서는 진행 중 훈련 취소를 지원하지 않는다.

동시 훈련 과부하 배수: `multiplier(n) = 1 + 0.4 × (n - 1)`
각 작업의 프레임별 진행량: `progress += deltaTime / multiplier(activeJobCount)`

한 판이 20~25분이므로 **기본 훈련 시간은 분 단위가 아니라 초 단위**여야 한다. 잠정 기준값 **45초**:

| 동시 작업 수 | 배수 | 기본 45초 기준 예상 시간 |
|---:|---:|---:|
| 1 | 1.0 | 약 45초 |
| 2 | 1.4 | 약 63초 |
| 3 | 1.8 | 약 81초 |

3병과를 전부 3단계까지 올리면 순차 진행 기준 약 7분이 걸린다 — 한 판의 3분의 1이다. 이 정도면 "다 올릴 수는 없고 골라야 하는" 압박이 생긴다.

활성 작업 수가 달라질 때 서버가 남은 시간을 다시 계산한다. 작업에는 `AccumulatedProgress`, `BaseDuration`, `LastServerTick`을 저장해 클라이언트 시간 조작에 의존하지 않는다.

> ⚠️ 훈련 시간·미니언 투입 간격·매치 길이는 **하나의 시간 축**이다. 20~25분 안에 1페이즈 개척 + 2·2.5·3페이즈가 들어가야 하므로, `MinionPhaseConfig`를 정할 때 훈련 1단계가 어느 페이즈에 걸치는지 반드시 함께 본다. 45초는 잠정값이며 `m1-balance-01`에서 확정한다.

#### 부상 회복

- 훈련관이 생존한 수비 몬스터의 HP를 매치 재화로 즉시 회복한다.
- 회복은 훈련 작업이 아니므로 동시 훈련 개수와 과부하 배수에 포함하지 않는다.
- 사망 개체는 회복할 수 없다.

#### 재화 분리 규칙

- **매치 재화**: NPC 거래, 제작, 강화, 수리, 몬스터 구매·훈련, 시설 복구, 파병 비용에 사용한다.
- **계정 재화**: 로비 또는 메타 해금에만 사용한다. 마을 NPC가 직접 소비하지 않는다.
- 서로 다른 수명의 재화를 같은 필드나 같은 저장 키로 합치지 않는다.

#### 공식 패키지 혼합 정책

- 영구 계정 필드는 공식 [`player-data-package`](https://github.com/MSW-Git/MSWPackages/blob/main/player-data-package/README.md) 코어와 저장 키 충돌을 조사한 뒤 어댑터 뒤에 통합한다.
- 업적은 공식 [`quest-achievement-package`](https://github.com/MSW-Git/MSWPackages/blob/main/quest-achievement-package/README.md) 코어를 같은 저장 진입점 뒤에서 사용한다.
- 공식 상점·인벤토리·재화 패키지는 영구 저장과 WorldShop 전제가 강하므로 M1 매치 전용 경제에는 그대로 사용하지 않는다.
- 도감은 기존 `MonsterCatalog`와 `AccountProfile.Collection`을 연결한 전용 데이터로 구현한다.
- 패키지 샘플 UI·관리자 도구는 가져오지 않으며, 영구 저장 진입점은 하나의 `PlayerDBManager`로 통합한다.
- `AccountProfile`은 `SchemaVersion`을 필수로 가지며 M1 최초 버전은 `1`이다. 패키지 고유 저장 키와의 충돌 여부는 Phase 0 감사 결과에 기록한다.
- **탈락 시점과 매치 종료 시점 모두** 보상 계산 → 중복 방지 정산 ID 생성 → AccountProfile 저장 성공 확인 → 상태 폐기 순서로 실행한다.
- 영구 저장 실패 시 정산 ID와 보상 델타를 서버 재시도 큐에 남기고, 같은 정산 ID를 두 번 지급하지 않는다.

### 4.11 NPC 배치와 데이터 원칙

- NPC는 `.map`에 직접 중복 배치하지 않고 CSV 기반 스포너 하나로 생성한다.
- `안농/RootDesk/MyDesk/NpcInfo.csv`는 NPC ID·이름·모델 원본이다. (2026-08-27 기준 **68행**)
- `안농/RootDesk/MyDesk/MapNpcs.csv`는 맵별 NPC 위치의 단일 기준이다. (2026-08-27 기준 **82행**)
- 신규 `FunctionalNpcCatalog.csv`는 `CatalogNpcId,RoleKey,DisplayName,UiGroupName,UiRoute,ActionRoute,OwnershipMode,SectorId,SlotOrder`를 가진 기능 계약의 단일 기준이다.
- **기존 `MapNpcs.csv` 행은 전부 보존한다.** 기능 NPC의 기본 위치는 `VillageNpcSector` 앵커 + `SlotOrder`이며, 개별 위치가 필요한 경우에만 선택적 `MapNpcs_Village.csv` 오버라이드를 추가한다.
- 기존 장식 NPC는 `FunctionalNpcCatalog`에 행이 없으므로 기능 상호작용 대상으로 취급하지 않는다.
- 기능 NPC 키는 네이티브 숫자 ID를 재사용하지 않고 `VD_` 접두사의 문자열을 쓴다. 예: `VD_WORKSHOP_CRAFT`, `VD_COMMON_DISPATCH`.
- **BL-009의 `NpcCatalog`/`NpcSpawner`가 이 명세의 NPC 생성 기반이다.** 현재 "표까지만" 지시로 스포너가 미구현 상태이며, Phase 1에서 이 잠금을 해제해야 한다.
- 역할 10개를 6개 마을에 배치하므로 기능 NPC 런타임 인스턴스 목표는 **60개**다.
- 마을은 `WORKSHOP`·`LIFE`·`RECORD`·`DEFENSE` 4구역으로 나누고, 맵마다 구역 앵커는 달라도 한 구역 안의 NPC 순서와 가까운 역할 묶음은 동일하게 유지한다.
- 좌표 해석은 **개별 `MapNpcs_Village` 오버라이드 → `VillageNpcSector` 앵커 계산 → 스폰 건너뜀+경고 로그** 순서다. 공용 NPC 2종은 앵커 대신 개별 오버라이드로 배치한다.
- `SpawnByModelId`의 parent는 반드시 대상 맵 엔티티다. `nil`을 넘기지 않는다.

### 4.12 기록 구역

#### 도감·업적 기록관

- 계정 단위 몬스터 발견·처치·특수 조건 달성 기록을 보여준다. 매치가 끝나도 유지된다.
- 도감 보상과 업적 보상은 서버에서 1회 수령 여부를 검증한다.
- M1은 기존 `MonsterCatalog`의 ID를 도감 키로 사용한다. (안농 도감 78종 기준)

#### 통계 분석관

자신을 제외한 **현재 생존자 전원**을 목록으로 보여준다(인원 가변이므로 고정 5인이 아니다). 목록에서 한 명을 선택하면 상세 패널을 갱신한다. 실제 아바타 전시 엔티티는 만들지 않는다.

공개 허용 필드:

- 아바타 외형과 장착 장비 / 매치 레벨 / 마을 성장도 / 보스 처치 수 / 몬스터 처치 수
- **현재 전선 단계**(1차/2차/억제기/코어) — 누가 앞서는지, 누구를 노릴지 판단하는 근거

비공개 필드:

- 매치·계정 재화 / 창고 내용 / 방어 시설 레벨·HP·파괴 상태·배치 / 수비 몬스터 종류·개체 수·HP·훈련 레벨 / 파병 편성

서버는 내부 플레이어 상태 전체를 클라이언트에 보내지 않고, 허용 필드만 복사한 `PublicPlayerSummary`를 반환한다.

집계 정의:

- `BossKillCount`는 **보스 처치 판정(최다 누적 피해)을 받은** 서버 이벤트 횟수다.
- `MonsterKillCount`는 일반 사냥 몬스터 처치 보상을 받은 서버 이벤트 횟수다.
- `LineStage`는 자기 마을의 현재 전선 단계(1~4)다. 낮을수록 잘 버티고 있다는 뜻이다.
- `VillageGrowth`는 숨은 자원량을 역산하지 못하도록 액션별 성장 포인트를 누적한 정수다. 시설 최초 강화, 병과 훈련 완료, 제작 도감 최초 완성, 수비 몬스터 최초 모집에 데이터 정의 `GrowthPoint`를 1회 가산한다.
- 같은 액션 키의 반복 소비로 성장 포인트를 무한 획득하지 않으며, 동률은 같은 값으로 표시한다.
- **K/D는 M1에서 제거한다.** 플레이어 간 직접 PvP가 이 게임에 존재하지 않으므로 항상 0인 필드를 두지 않는다.

### 4.13 UI 원칙

- **레인 HUD가 최우선이다.** 현재 페이즈, 내 전선 단계(1차/2차/억제기/코어), 각 시설 HP, "파병 섞임" 경고를 항상 보이게 둔다.
- NPC 상호작용 UI는 한 번에 하나만 열린다.
- 공통 팝업 프레임, 확인/취소 버튼, 비용 표시, 결과 토스트를 재사용한다. (기존 `style-4-blue` 메이플식 번들 재사용)
- 통계 UI는 ‘생존자 목록 + 선택 상세’ 구조다.
- 훈련 UI는 병과별 레벨, 진행률, 서버 기준 남은 시간, 현재 동시 작업 배수를 보여준다.
- 포탑 관리 UI는 1차·2차·억제기·코어를 한 화면에 놓고 각각의 HP·레벨·비용을 보여준다.
- 파병 UI는 대상 선택 → 편성 → 신청 순서다. 기존 파병 리모컨을 재사용한다.
- 모든 구매·강화·수리 버튼은 클라이언트 예상 결과를 보여주되, 실제 성공 여부와 최종 수치는 서버 응답을 따른다.
- `.ui` 파일은 UIBuilder를 통해서만 만들거나 수정한다.

> ⚠️ **UI 클릭 함정**: `.ui` 클릭 버튼을 UIGroup 루트 직속에 두면 실제 클릭이 먹지 않는다. 반드시 컨테이너에 중첩한다.

- 모든 신규 창은 1920×1080 `DefaultType(1)` 그룹, `GroupOrder=2`, `DefaultShow=false`의 공통 셸을 쓴다. `BattleHUD=0 < StatusHUD=1 < 신규 창=2 < PopupGroup=3 < ToastGroup=6` 순서를 유지한다.
- 창 루트에는 입력을 막는 `Dimmer`를 두고, 닫기·탭·실행 버튼은 반드시 `Window` 아래에 중첩한다. 한 번에 하나의 NPC/캐릭터 창만 열 수 있다.
- `NpcOpenedEvent`의 `UiGroupName`/`UiRoute`를 받는 ClientOnly 라우터 하나가 열기·라우트 전환·다른 창 닫기를 소유한다. NPC가 늘어도 라우터 분기를 추가하지 않는다.
- 서버 왕복 직전 실행 버튼을 끄고, 응답 이벤트가 올 때만 UI를 갱신한다. 클라이언트 낙관적 성공 처리와 `any` payload는 금지한다.
- 장비·보석 아이콘은 `ItemInfo.IconRUID`/`GemInfo.IconRUID`로 런타임 주입한다. 빈 RUID는 오류 없이 안 보이므로 PR에 미주입 노드를 적는다.

### 4.14 플레이어 스탯과 전투

- 최종 스탯은 서버 `StatService` 한 곳에서만 `BaseStat + EquipStat + EnhanceStat + BuffStat` 순으로 합산한다. `BaseStat`은 직업 기본치와 레벨업 AP 자동 분배 누적이며, Buff는 스킬 도메인 예약값이다.
- 스탯 13종은 STR·DEX·INT·LUK·공격력·마력·방어력·이동속도·점프력·명중·회피·최대 HP·최대 MP다. 보석 12종은 방어력을 제외한 능력치와 1:1이고, 방어력은 방어구 고유값과 강화 `AddDefense`로 올린다.
- 물리 데미지는 `(주스탯 × 4 + 부스탯) × 총공격력 ÷ 100`을 기준으로 무기 숙련도 범위 안에서 무작위로 정한다. 명중 실패는 0, 방어 감산은 `max(1, Raw × (1 - Defense / (Defense + DefenseK)))`이며 난이도 배수는 서버 한 지점에서만 적용한다.
- `PlayerAttack.CalcDamage`의 고정값과 항상 참인 크리티컬 판정은 스탯·확률 기반 계산으로 교체한다. 스킬 계수 해석과 `JobInfo`의 주/부스탯·AP 비율은 B와 확정한 계약만 사용한다.
- AP는 레벨업 때 직업 비율로 자동 분배한다. SP는 `match_sp` 원장을 A가 보유하고 B가 `SpSpentEvent`로 소비를 통보한다.
- 이동속도와 점프력은 플레이어 컴포넌트가 현재 맵 물리 규칙에 맞춰 반영한다. MapleTile의 체감 계수는 구현 전 실제 플랫폼 규칙으로 확인하며 숫자를 추측해 넣지 않는다.

### 4.15 아이템 · 장비 · 강화

- 장비 슬롯은 `WEAPON`·`HAT`·`TOP`·`BOTTOM`·`SHOES`·`GLOVES` 여섯 개다. `ItemInstance`는 `InstanceId`·`ItemId`·`EnhanceLevel`·`Durability`·`AppliedGemsCsv`를 가지며 매치 종료 시 폐기된다.
- `ItemInfo`는 장비 기본 스탯·요구 조건·내구도·숙련도·아이콘의 단일 기준이다. 장착/해제는 서버에서 슬롯·직업·레벨을 검증하고 `EquipChangedEvent` 뒤에 스탯을 재계산한다.
- M1 강화는 1~3단계, 성공률 100%, 파괴율 0으로 시작한다. 보석 선택이 오르는 능력치를 정하며, 강화 성공은 `ItemEnhancedEvent` → `GemSpentEvent` → `StatRecalculatedEvent` 순서로 화면과 상태를 갱신한다.
- 인벤토리·장비·강화 목록은 RPC 경계에서 table을 보내지 않고 문자열로 직렬화한다. 강화 미리보기는 클라이언트 예상값일 뿐, 최종값은 서버 응답이 정한다.

### 6.3 데이터 정합성 규칙

- 모든 참조 ID는 시작 시 서버에서 검증하고 누락·중복을 로그로 남긴다.
- 여섯 VillageId는 정확히 하나의 마을 맵과 두 개의 레인 사냥터를 가져야 한다.
- 기능 NPC는 각 마을에 10개 역할이 정확히 한 번씩 존재해야 한다.
- 로비 안내와 파병 접수 공용 NPC는 해당 공용 맵에 정확히 한 번씩 존재해야 한다.
- 같은 `CatalogNpcId`가 반복돼도 모든 런타임 `NpcInstanceKey`는 현재 MatchId 안에서 고유해야 한다.
- `MapNpcs`의 좌표는 월드 단위이며, CSV 행과 `.map` 직접 배치가 동시에 존재해서는 안 된다.
- **`MinionPhaseConfig`의 네 페이즈(1 · 2 · 2.5 · 3)가 모두 정의되어야 하고, 각 페이즈에 최소 1개의 `MinionComposition` 행이 있어야 한다.**
- **`LaneConfig`는 여섯 마을 전부에 대해 레인 3맵의 하단 길 x범위와 4개 슬롯 좌표를 가져야 한다.**
- **`DifficultyConfig`는 1~5 다섯 행이 모두 있어야 하고, 배수 적용은 서버 한 곳에서만 한다** (각자 곱하면 이중 적용·누락이 생긴다).
- 상시 전투 구조이므로 "전투 결과 스냅샷" 개념은 없다. 대신 **포탑 파괴와 전선 이동은 각각 1회성 이벤트**이며 같은 것을 두 번 반영하지 않는다.
- `FunctionalNpcCatalog`의 마을 역할은 각 `SectorId`와 양의 `SlotOrder`를 가져야 하며, 같은 마을·섹터에서 계산된 좌표가 겹치면 시작 시 경고한다. 공용 역할은 명시적 개별 좌표 없이는 스폰하지 않는다.
- `ItemInfo`의 장비 슬롯은 `EQUIP` 행에서만 유효하고, `EnhanceTable`의 강화 단계는 중복되지 않아야 한다. 인벤토리·장비 목록 DTO는 ExecSpace 경계에서 문자열이어야 한다.
- `GemInfo.StatId`는 `StatId` 13종 중 하나여야 하며, `GemDropTable`의 `SourceKind`·`SourceId`는 실제 몬스터·엘리트·보스를 가리켜야 한다.

- ⬜ **초기 장비 6종·`ItemInfo`·인벤토리·6슬롯 장착과 `CharacterGroup` 구현** — 장착/해제 전후 스탯 합산과 아이콘 런타임 주입 검증
- ⬜ **보석 12종 `GemInfo`/`GemDropTable`·`EnhanceTable` 작성과 강화 소모처 배선** — M1은 1~3단계·성공률 100%·파괴율 0으로 검증
- ⬜ **마노 선취 보상(10렙제 체력 갑옷 + 메소) 구현 — 선착순 1회 검증**
- ⬜ 공유 사냥터 몬스터·미니언 처치 보상을 원장에 연결
- ⬜ **보스 누적 피해 원장과 최다 피해자 처치 판정 구현**
- ⬜ 제작·강화·플레이어 장비 수리·물약 구매 구현
- ⬜ 매치 전용 창고 입출고 구현
- ⬜ 몬스터 개체 구매와 보유 목록 구현
- ⬜ 병과별 훈련 작업, 동시 작업 배수, 서버 시간 진행 구현
- ⬜ 생존 수비 몬스터 즉시 회복과 사망 개체 제거 구현
- ⬜ **포탑 관리 액션(1차·2차·억제기·코어)의 비용·레벨·HP 상태 구현**
- ⬜ 역할별 공통 팝업과 실패 토스트 구현
- ⬜ 모든 비용·소유권·중복 요청을 서버 권위로 검증

완료 기준: 실제 사냥·엘리트·보스 보상으로 구매·제작·훈련·포탑 투자를 수행하고, 같은 매치 흐름에서 상태가 일관되게 유지된다. 대체 테스트 재화만으로는 완료 처리하지 않는다.

### Phase 3 — 파병·누적 피해·주니어 발록

목표: 유일한 원격 공격 수단을 완성하고, 승리 조건인 발록을 실제로 연결한다.

- ⬜ **슬리피우드 맵을 세계에 등록** (`SectorConfig` + `PortalRoutes` — 현재 완전 미등록)
- ⬜ **주니어 발록 몬스터 제작** (도감 77종에 없다 — `.model` + 도감 행 신규)
- ⬜ **발록 도전 NPC 구현: 메소 지불 → 개인 채널 입장**
- ⬜ **개인 채널(솔플 인스턴스) 구현 방식 확정 및 구현** — MSW에서 어떻게 격리할지 미검증
- ⬜ **발록 선취 판정 → 매치 승리 → 전원 종료 구현 (중복 방지)**
- ⬜ **마노 몬스터 제작** (도감에 없다. 현재 `LithHarbor_Boss_Mano`엔 Lv3~5 잡몹만 있다)
- ⬜ `DispatchService` 구현: 대상 선택, 편성, 취소, 동시 상한 검증
- ⬜ 파병 몬스터가 미니언 흐름에 합류해 함께 진격하는 통합
- ⬜ 파병 시 보유 목록에서 즉시 제거·취소 시 복귀 처리
- ⬜ 파병 리모컨 UI 재사용·개조 (문자열 직렬화 유지)
- ⬜ 방어자에게 "파병 섞임" 경고만 노출하고 발신자·구성은 숨기는 정보 계약 구현
- ⬜ 수비 몬스터 배치·팀 판정 구현 (`MINION/DEFENDER`)
- ⬜ 시설 HP·파괴, 몬스터 HP·사망의 원자적 반영 구현
- ⬜ 파괴 시설 재건·수리·생존 몬스터 회복이 이후 전선에 반영되는지 검증
- ⬜ 동일 파괴 이벤트 중복 반영 방지 테스트

완료 기준: 발록을 먼저 잡은 사람이 승자로 판정되어 매치가 끝나고, 파병이 실제로 상대의 전선을 밀며, 복구하지 않은 파괴 시설과 사망 개체가 자동 복원되지 않는다.

### Phase 4 — 기록·영구 성장·공개 통계

목표: 매치 데이터와 계정 데이터를 분리하고, 기록 NPC 두 종류의 완성 UI를 제공한다.

- ⬜ 공식 플레이어 데이터·업적 패키지의 저장 키, 관리자, 샘플 의존성 감사
- ⬜ 단일 `PlayerDBManager`와 `AccountProfile` 통합
- ⬜ 기존 `MonsterCatalog`(77종 + 신규 발록·마노) 기반 영구 도감 진행도 구현
- ⬜ 업적 진행·1회 보상 수령 구현
- ⬜ 생존자 `PublicPlayerSummary` 서버 생성 구현 (전선 단계 포함, 인원 가변)
- ⬜ 생존자 목록 + 선택 상세 통계 UI 구현
- ⬜ 비공개 필드가 네트워크 DTO와 UI에 포함되지 않는지 검사
- ⬜ **패배 시점 정산과 발록 선취 종료 시점 정산 양쪽에서 AccountProfile 보존 검증**

완료 기준: 패배하거나 매치가 끝나면 장비·재화·시설·몬스터·훈련은 사라지고, 도감·업적·계정 성장만 다음 세션에서 복원된다.

### Phase 5 — 6개 마을 확장과 통합 검증

목표: 수직 조각을 여섯 마을 전체로 확장하고 다인 동시 플레이 조건에서 릴리스 기준을 통과한다.

- ⬜ Phase 0 기준선에 `안농`의 나머지 마을 맵과 NPC CSV를 통합
- ⬜ 기존 `MapNpcs.csv` 행을 보존하며 60개 기능 NPC 배치 데이터 완성
- ⬜ **나머지 5개 마을 × 레인 3맵 = 15개 맵의 하단 1자 길 + 밧줄 지형 작업** (Maker UI, 이 마일스톤 최대 물리 작업)
- ⬜ **커닝시티 레인 4단 예외 처리** (`Village_SubwayEntrance`를 통과시킬지 포탑을 둘지)
- ⬜ 6개 마을 전부에 코어·포탑 3종 앵커 배치 및 동작 검증
- ⬜ **마을 간 레인 난이도 편차를 `LaneConfig`로 보정하고 명백한 유불리가 없는지 확인**
- ⬜ 2인·4인·6인 각각에서 마을 선점 경쟁, NPC 권한, 생존자 통계 목록 검증
- ⬜ 6개 레인 동시 진행 부하, 파병 상한, 이탈·재접속, 매치 강제 종료 예외 검증
- ⬜ 통합 월드의 모든 맵을 열거하고 샘플·임시 엔티티 후보를 목록화
- ⬜ 사용자가 미사용 템플릿 맵·플레이스홀더를 확인한 뒤 승인된 항목만 제거
- ⬜ Maker Refresh → Play → build/normal 로그 → 핵심 UI·전투 동작 최종 검증

완료 기준: 한 Room의 2~6명이 각자 한 마을과 10개 NPC를 소유하고, 미니언 4페이즈를 끝까지 진행해 발록 선취 승자가 나오며, 다른 Room 또는 다음 매치로 상태가 새지 않는다.


## 8. M1에서 확정한 것과 확정하지 않은 것

### ✅ 확정

- 2~6인 가변 매치, 목표 길이 **20~25분**
- **전원 1레벨 시작. 10레벨 전직 → 마을 코어 연결 → 선착순으로 마을 주인.** 배정이 아니라 쟁취다
- 코어 연결 전에는 포탑·모집·훈련·기능 NPC를 쓸 수 없다
- 정확한 6개 마을 allowlist / 마을당 기능 NPC **10개** (터렛·벙커 관리관 폐기, 포탑 관리관 1명)
- **⛔ 전용 수비 맵을 만들지 않는다.** 기존 사냥터가 방어 레인을 겸한다
- **방어 레인** = `여섯갈래길 → 사냥터2 → 사냥터1 → 마을`. 각 맵 아래쪽 1자 길로 미니언이 걷고, 플레이어는 밧줄로 내려가 개입한다
- **4단 방어선**: 1차포탑(사냥터2) → 2차포탑(사냥터1) → 억제기(2차 뒤) → 코어(마을)
- **억제기 파괴 = 미니언 강화 + 미니언 경험치 소폭 상승.** 내주는 것이 순수한 손해가 아니다
- 마을 건물에 HP 없음. 부술 수 있는 것은 포탑 3종과 코어뿐
- **미니언 4페이즈**(1 없음 / 2 저공격 / 2.5 고공격 / 3 전면 상승). **전환은 매치 경과 시간 기준**, 레벨은 기대치일 뿐
- **21레벨(3페이즈) 전에는 플레이어 공격이 포탑·억제기에 거의 안 통한다.** 21레벨부터 남의 마을 침범 가능
- 유일한 원격 공격 수단은 파병. **파병 몬스터는 미니언에 합류하고 돌아오지 않는다**
- 사냥터는 전원 공유. 보스는 최다 누적 피해자가 독식
- **리스항구는 1페이즈 전용**(Lv1~5). **마노 선취자에게 10렙제 체력 갑옷 + 메소**
- **엘리트 몬스터** — 확률 스폰, 전용 재료 재화 단독 드롭, 성장 필수
- 매치 자원: **메소 · 경험치 · 보석 12종 · 엘리트 재료**. 전부 매치 종료 시 소멸
- **승리 = 슬리피우드 주니어 발록 선취** (메소 지불, 개인 채널 솔플)
- **패배 = 코어 파괴.** 별도 제한 시간 없음 — 25분경 난이도 곡선이 실질 타이머다
- 영구 데이터에는 공식 패키지 코어를 선택적으로 통합하는 혼합 정책

| **CoreVersion 병합 실패** | 전체 일정 정지 | Phase 0을 게이트로 두고, 실패 시 Phase 1을 시작하지 않음 |
