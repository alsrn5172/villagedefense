# 팀 파이트 + 파밍 / 소환 시스템 (map01)

기존 Faction 팀 전투장(`map01`, MapleTile)을 **"위층에서 파밍해 경험치·메소를 모으고, 그 자원으로 1층 벽에서 아군(TeamA)을 소환해 적(TeamB)과 싸우는"** 실시간 대전 게임으로 확장한 결과 문서.

> 상태: **구현 완료 + 플레이 모드 검증 완료** (2026-07-24)

---

## 1. 한눈에 보는 구조

```
 5층 (y=7.0)  파밍: 주니어 예티 (exp 10)        ┐
 4층 (y=5.2)  파밍: 좀비버섯   (exp 5)          │ 파밍 몹만 15초 리스폰
 3층 (y=3.4)  파밍: 초록 슬라임 (exp 1)          ┘
 2층 (y=1.76) 비움 (기존 잔디 플랫폼)
 1층 (y=-0.04) 팀 전투장 ── TeamA벽(좌) / TeamB벽(우) / 포탑 A·B
        ▲ 사다리 4개로 1→5층 등반
```

- 플레이어(TeamA)가 **위층 몹을 잡아** 경험치(레벨)·메소(동전) 획득
- 좌측 UI로 **TeamA 소환**(자원 소모), 우측 UI로 **TeamB 소환**(리모컨, 제한 없음)
- 소환 유닛끼리 1층에서 팀 파이트, **파밍 몹 외에는 리스폰 없음**

### 몬스터 도감 (고유번호 기반, 2026-08-10 추가)

파밍 몹의 **이름·레벨·EXP·동전은 데이터셋이 단일 진상**이다. 코드/모델을 고치지 않고 표만 바꾼다.

| 파일 | 열 | 역할 |
|---|---|---|
| `RootDesk/MyDesk/MonsterInfo.csv` | `Id, Name, Level, Exp, CoinMin, CoinMax, ModelId` | 고유번호별 도감. **여기 한 줄 고치면 월드맵 툴팁 + 실제 처치 보상이 동시에 바뀐다** |
| `RootDesk/MyDesk/MapMonsters.csv` | `MapName, MonsterId, X, Y, #Note` | **실제 스폰 테이블.** 한 행 = 스폰 자리 1개. `#Note` 에 "3층 1번자리" 메모 |
| `RootDesk/MyDesk/LevelTable.csv` | `Level, NeedExp, AddMaxHp, AddMaxMp, AP, SP, #Note` | 레벨 성장표(Lv50까지). `NeedExp` = 그 레벨에서 다음 레벨로 갈 때 필요한 exp |

- 읽는 쪽: `Catalog/MonsterCatalog.mlua`(@Logic, 서버·클라 양쪽 적재)
  → `FarmSpawner`(스폰) / `FarmReward`(보상) / `WorldMapController`(툴팁) / `SummonManager`(레벨)
- **월드맵 툴팁의 몹 목록은 스폰표에서 파생**(`GetMapMonsterIds` = 중복 제거)이라 표시와 실제가 어긋날 수 없다.
- 각 `FarmMobTn` 모델에는 `script.FarmReward.MonsterId` 가 박혀 있다(T1=1001 / T2=1002 / T3=1003).
- 모델의 `ExpAmount`/`CoinMin`/`CoinMax` 는 **도감에 행이 없을 때만 쓰이는 폴백**으로 남겨 뒀다.
- **HP 는 도감에 없다.** 여전히 각 모델 `script.Monster.MaxHp`(T1 30 / T2 80 / T3 200).
- 새 몹 추가: `MonsterInfo` 에 행(+`ModelId`) 추가 → `MapMonsters` 에 스폰 자리 행 추가.
  그러면 **실제로 그 맵에 등장하고** 월드맵 툴팁에도 자동 반영된다(툴팁 행 최대 5개까지 자동 확장).
  단 **새 종류의 몹은 `.model` 이 먼저 있어야 한다**(그림·애니메이션 RUID는 모델 소유).

### 파밍몹 스폰 (2026-08-19 변경)

예전엔 파밍몹 9마리가 각 `.map` 에 **직접 배치**돼 있었다. 표시(도감)와 실제(배치)가 어긋나는 문제 때문에
**테이블 스폰으로 이전**했다. `.map` 의 배치 27개(3맵×9)는 제거됨 — 다시 넣으면 이중 스폰이 된다.

- `Farm/FarmSpawner.mlua` (`@Component`) 를 **각 맵 루트**(map01/02/03)에 부착. 맵 로드 시 자기 맵 몫만 스폰.
- 스폰 좌표: 3층 y=3.5 / 4층 y=5.435 / 5층 y=7.235, x = −3·0·3 (4·5층은 −2.977·0.023·3.023).
- 리스폰은 그대로 `script.Monster` 의 `RespawnOn`/`RespawnDelay` 담당(런타임 스폰본도 정상 동작).

### 캐릭터 스탯 / 상태창 (2026-08-19 추가)

- `ui/StatusHUD.ui` — 사용자가 붙인 MSW 상태창 프리셋(`UIMyInfo`)을 `BattleHUD` 에서 **분리**한 것.
  분리 이유: 월드맵을 열면 `BattleHUD` 의 좌우 리모컨이 접히는데, 상태창은 계속 보여야 한다.
- `Summon/StatusHUDController.mlua` (`@Logic`) — 바 3개 갱신. **UI 엔티티 `@Component` 로는 서버 RPC 를
  못 받으므로**(UI는 클라 전용) 반드시 @Logic 이다.
  - **HP**: 네이티브 `PlayerComponent.Hp/MaxHp` 를 클라에서 직접 폴링(피격 즉시 반응)
  - **MP / EXP / 레벨 / AP / SP**: 서버 `SummonManager` 권위 → `PushStats` 로 푸시
  - 바는 `img_bar` 의 `RectSize.x` 를 비율만큼 줄여 표현(전체폭 330)
- **MP 는 엔진에 없다** → `SummonManager.econ` 이 진상(`mp`/`maxMp`). 기본 `BaseMaxMp = 100`.
- 레벨업: `LevelTable` 의 `AddMaxHp`/`AddMaxMp` 만큼 최대치 상승 + HP·MP 가득 회복 + `AP`/`SP` 지급.
  **AP/SP 는 지급·표시만 하고 쓰는 기능은 아직 없다.**
- 레벨업 연출: `SummonManager.LevelUpEffectRUID`(황금빛 상승 폭발) + `LevelUpSoundRUID`.
  인스펙터에서 교체 가능하고, 비우면 그 부분만 생략된다.

### 파밍 몹 배회 (FarmPatrol)
- **1초마다 좌/우/정지 중 하나를 랜덤**으로 골라 수행(계속 같은 방향일 수도 있음).
- **막다른 길(발판 끝)에 닿으면 즉시 방향 전환.** 착지 시 "같은 높이로 이어진 발판 체인 전체의 좌/우 끝(MinX~MaxX)"을 1회 계산해 캐시하고 그 안에서만 왕복 → **사용자가 그린 어떤 발판에도 자동으로 맞고, 밖으로 안 떨어진다**. (`PredictFootholdEnd` 는 한 세그먼트만 봐서 못 씀 → 발판 체인 순회로 대체)
- 이동 속도 `Speed`(T1 1.0 / T2 0.9 / T3 0.8), 정지 시 `StandRUID` 그림. 방향은 Scale.x 부호로 표시.
- 사망 시 정지+사망 그림, 리스폰 시 다시 배회. 넉백 0.

### 팀 몹 전진 (FactionAI)
- 팀 몬스터는 **적 포탑 방향으로 계속 전진**한다. **TeamA→오른쪽(+1)**, **TeamB→왼쪽(-1)** (`Faction.Team` 자동 판정, `AdvanceDir` 로 강제 가능). **중립(Neutral)은 그 자리 정지.**
- 전진 중 사거리(`AttackRange`) 안에 적이 들어오면 그 자리에서 공격, 처리 후 다시 전진. (예전 ROAM/CHASE 랜덤 배회 제거)
- 배치본·소환본 모두 같은 스크립트라 자동 적용. 포탑 생존과 무관하게 방향 유지.

### 발판 그림 (에디트에서도 보이게)
- 발판 그림은 `SpriteRendererComponent.DrawMode=Tiled` + `TiledSize=(24, 0.6)`를 **모델에 구워** 에디트/플레이 모두에서 전체 폭(≈12칸)으로 보인다. (예전엔 런타임에만 타일링돼 에디트에서 "투명발판"처럼 보였음)
- 발판 콜리전(±6)은 여전히 `MapPlatform`이 런타임 등록(`MapBuilder`가 발판 저작 미지원).

## 4. 핵심 설계 결정

- **파밍 몹은 Faction 컴포넌트 없음(중립)** → 팀 전투의 적 탐색(`script.Faction` 홀더만 수집)에 안 잡혀 **위층 파밍이 아래 전투에 간섭하지 않음**. 대신 `PlayerAttack` 에서 파밍 몹만 예외적으로 때릴 수 있게 처리.
- **경제 상태는 서버 테이블 + Client RPC push** — 런타임 `AddComponent` 컴포넌트의 클라 복제 불확실성을 피하려고, 서버(`SummonManager.econ`)가 단일 권위를 들고 값 변경 시마다 소유 클라의 `BattleHUDController:PushEconomy` 로 전달.
- **커스텀 발판은 런타임 등록** — `MapBuilder` 가 발판 저작을 지원하지 않아, `MapPlatform` 이 `OnBeginPlay` 에서 `CustomFootholdComponent.edgeLists` 로 수평 발판을 만든다(`IsDynamicFoothold=true`).
- **동전 획득은 근접 판정** — 충돌 매트릭스에 의존하지 않고 서버가 맵의 플레이어를 훑어 `PickupRadius` 안이면 획득(기존 FactionAI/Aura 와 같은 철학).

## 6. 참고 / 튜닝 포인트

- **포탑도 리스폰 X** 로 설정됨("밑에서 싸우는 애들" 규칙). 포탑만 리젠하려면 `TurretA/B` 모델 `Monster.RespawnOn = true` 로 되돌리면 됨.
- 모든 수치(HP·경험치·메소·코스트·소환 위치·오라 값·동전 개수)는 인스펙터 프로퍼티 → 코드 수정 없이 조정 가능.
- 소환 유닛 스프라이트/티어/색은 모델·`SummonManager` 설정으로 교체 가능.
- 테스트 툴(`mouse_input`)은 엔진 UI 버튼을 못 눌러, 버튼 클릭은 `ButtonClickEvent` 직접 발생으로 검증함. 실제 플레이에서는 버튼 클릭이 정상 동작.
