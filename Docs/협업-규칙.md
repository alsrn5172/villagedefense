## 0. 이 방식이 무엇인가 (30초)

MSW에는 공동 제작 방식이 **두 가지**고 **동시에 못 쓴다.**

| | Cooperation | **LocalWorkspace (우리)** |
|---|---|---|
| 편집 | Maker 안에서만 | **로컬 파일을 외부 도구로** |
| 잠금 | 자동 Check Out/In | **없음 → 사람이 규칙으로** |
| 형상 관리 | Revision(월드 스냅샷) | **git (브랜치·PR·diff)** |
| AI 에이전트 | 불가 | **가능** |

AI로 작업하므로 LocalWorkspace를 쓴다. **대신 MSW가 자동으로 걸어주던 파일 잠금이 없다.** 이 문서의 절반은 그 빈자리를 메우는 규칙이다.

---

## 1. 🔴 가장 중요한 규칙 6개

1. **`.map` / `.ui` / `.model` 은 파일당 담당자 한 명.** 남의 파일을 열지 않는다
2. **git 조작 전에 Maker를 끈다.** Maker는 메모리 내용으로 디스크를 되쓴다
3. **`git pull --no-rebase` 를 쓴다** (§5-1 이유 참조 — rebase는 충돌 해결 명령의 의미를 뒤집는다)
4. **커밋 전 `git status` 로 확인하고 내 파일만 스테이징한다**
5. **새 표·열·열거값·이벤트·시스템은 [`스키마-계약.md`](스키마-계약.md)를 먼저 고친다**
6. **`.mcp.json` 을 커밋하지 않는다.** API 토큰이 들어 있다

## 2. 소유권

### 2-1. 파일 종류별

| 종류 | 규칙 | 왜 |
|---|---|---|
| **`.map` `.ui` `.model`** | 🔴 **파일당 담당자 1명** | 머신 생성 JSON이라 git이 자동 머지하면 **에러 없이 조용히 깨진다.** MSW도 공식적으로 로컬 직접 편집을 "지양"이라 한다 |
| `.mlua` | **폴더 단위 배정** (§2-2). 같은 폴더 안에서는 자유 | 텍스트라 git이 제대로 머지한다 |
| `.csv` | **행 추가 자유.** 기존 행 수정은 그 행 담당자만 | MSW가 공식적으로 자유 편집을 허용한 유일한 형식 |
| `.csv` **헤더** | 🔴 **공지 후 단독 작업** | `merge=union` 이라 두 사람이 고치면 헤더가 두 줄 되고 조용히 깨진다 |
| `.userdataset` | **커밋한다.** 거의 안 바뀐다(열 정의를 CSV 헤더에서 읽음). 충돌 시 **`.csv` 를 정본으로 보고 재생성** | 자동 머지 차단 대상 |
| `.codeblock` | 손대지 않는다. **커밋은 한다** | refresh가 생성. EntryKey가 결정론적이라 안전 |
| `스키마-계약.md` | 🔴 **공지 후 단독 작업** | 모두가 의존하는 계약이다 |
| `Global/SectorConfig.config` | 공용. 충돌 시 **양쪽 `entries` 를 모두 남긴다** | 맵 추가마다 한 줄씩 |

> "담당자 1명"은 **영구 지분이 아니라 동시에 한 명**이다. 끝내고 머지하면 다음 사람이 이어받아도 된다.

### 2-3. 🔴 이 배정의 현실

A가 M1의 약 85%를 갖는다. 그래서:

- **파일 충돌은 거의 안 난다** (한 사람이 대부분을 소유)
- 대신 **PR 리뷰가 사실상 성립하지 않는다** — 서로 도메인 지식이 없다
- **A가 병목**이 된다

**따라서**
1. **경계면에만 집중한다.** 진짜 계약이 필요한 건 두 곳뿐 — **스킬 ↔ 전투/몬스터**, **전직 ↔ 코어 연결 자격**
2. **self-merge 를 허용한다** (§3-3)
3. **B의 리뷰 범위를 좁힌다** — A의 PR에서 **"내 폴더·내 표·내 이벤트를 건드렸나"만** 본다

### 2-4. 🔴 전직이 크리티컬 패스에 있다

```
10레벨 → 전직(B) → 코어 연결 자격(A) → 마을·포탑·NPC·미니언 방어 전부
```

B의 작업이 A 골격 한가운데 있다. **`JobChangedEvent` → 코어 연결 자격 부여** 인터페이스가 최우선 계약 항목이며, B의 시스템 등록서에서 반드시 채워야 할 칸이다.

## 3. 브랜치와 PR

### 3-1. 기능 단위로 **세로로** 자른다

한 브랜치에 그 기능의 **전부**를 담는다 — `.ui` + `.mlua` + CSV 행 + 필요하면 임시 맵까지.

❌ 파일 타입으로 가로로 자르지 않는다("이 브랜치는 UI만"). 아무도 혼자 실행·테스트할 수 없는 반쪽 브랜치가 생기고, 합쳐지는 시점에야 처음으로 돌아가는지 알게 된다.

> ✅ **명시적 예외 2가지** — **이벤트 정의 PR**(§6-3)과 **시스템 등록 PR**(§6-5)은 **의도적으로 작게 자른 선행 PR**이다. 이건 가로 자르기가 아니라 순서 의존을 푸는 장치다.

- 브랜치 이름 `{담당}/{도메인}-{짧은설명}` — 예: `a/lane-tower-hp`
- **1~2일 안에 머지한다.** 오래 묵을수록 머지가 아니라 재작업이 된다
- `main` 직접 push 금지. **PR이 곧 "이 파일 내가 잡음" 선언**이고 머지되면 자동으로 풀린다
  > **서버가 막는다** — `main` 직접 push 금지 · PR 필수 · 필요 승인 0 · force push·삭제 차단 · 대화 해결 필수.
  > **예외 없다** — `enforce_admins: true`. 그룹장도 `main` 에 직접 못 민다(실측: `[remote rejected] protected branch hook declined`).
  > 되돌릴 일이 생기면 revert 커밋을 브랜치에 올려 PR로 머지한다. 로컬 훅은 서버에 닿기 전에 잡아주므로 계속 유지한다.
  > ⚠️ 이 보호는 **저장소가 공개라서** 가능하다. 비공개로 되돌리면 GitHub Free에서는 보호가 풀린다(403). 되돌릴 때는 훅이 유일한 방어선이 된다.

### 3-1-1. PR 흐름 — 🔴 **AI 는 push 까지, PR 은 사람이 한다**

| 단계 | 누가 |
|---|:--:|
| 브랜치 생성 · 작업 · 커밋 · **push** | **AI** |
| **PR 생성** | **사람** |
| 리뷰 · **머지** | **사람** |

**왜 나누나** — push 는 "작업물을 올린다"이고, PR 생성과 머지는 **"이걸 `main` 에 넣겠다"는 의사결정**이다.
의사결정은 사람 몫이다. AI 가 PR 을 열고 스스로 머지하면 검토 지점이 사라지고,
PR 이 "락 선언"으로 기능하지도 못한다(3-1).

#### AI 가 하는 것

```bash
git switch -c a/작업이름          # {담당}/{도메인}-{설명}
# ... 작업 · 커밋 ...
git push -u origin a/작업이름
```

여기서 멈추고 **브랜치 이름과 무엇을 했는지 보고**한다. `gh pr create` 를 부르지 않는다.

#### 사람이 하는 것

```bash
gh pr create --fill
```

```bash
gh pr merge --merge --delete-branch
```

⚠️ **`--merge` 로 고정한다.** `--squash` / `--rebase` 는 `pull.rebase=false` 규약과 어긋나고,
자동 머지를 꺼둔 `.map` `.model` `.ui` 계열의 히스토리 추적을 어렵게 만든다.

#### 큰 작업은 stacked PR 로 쪼갠다

이관·마이그레이션처럼 **중간 상태가 깨지는** 작업은 도메인별로 잘라 `main` 에 각각 머지하면 안 된다
(모델만 들어가면 맵이 없고, 맵만 들어가면 참조할 모델이 없다).

통합 브랜치를 하나 두고 조각들을 **그 브랜치로** PR 한다.

```
a/도메인-A ─┐
a/도메인-B ─┼─▶  a/통합브랜치  ──PR──▶  main
a/도메인-C ─┘
```

조각 PR 은 `--base` 로 대상을 통합 브랜치로 지정한다.

```bash
gh pr create --base a/통합브랜치 --fill
```

기능별로 리뷰는 나뉘지만 **`main` 에는 검증까지 끝난 것 하나만** 들어간다.
`main` 이 깨진 상태를 한 번도 거치지 않는다.

### 3-2. PR 리뷰에서 볼 것

1. **남의 파일이 섞여 있지 않은가** (Maker 저장 노이즈)
2. 새 표·열·열거값·이벤트·시스템이 있는데 **계약서 변경이 없으면 반려**
3. 런타임이 바뀌면 **검증 증거** — PR 본문에 **"빌드 경고 이전 N → 이후 N"** 을 적고 핵심 `log()` 출력을 붙인다. **"동작 확인함"이라는 말만으로는 통과시키지 않는다**
4. `.csv` 변경이 **행 추가**인가. 헤더를 건드렸다면 사전 공지가 있었는가
5. 이벤트 **구독** PR이면 → 정의 PR이 이미 머지됐는가
6. **테스트 게이트 코드가 남아 있지 않은가** (§10-1 닉네임 하드코딩)

### 3-3. self-merge · PR 락 만료

리뷰어가 1명뿐이라 "직접 push 금지 + 1~2일 내 머지"가 서로를 막을 수 있다.

- **자기 폴더 안에서 닫히는 PR**(계약서 §1 등록서 8번이 비어 있는 PR)은 **24시간 무응답 시 self-merge 가능**
- **경계면 PR**(8번이 비어 있지 않은 PR)은 **반드시 상대 승인**
- **PR 락은 7일 무활동 시 해제.** 해제 전 코멘트로 통지한다

### 3-4. 공지 채널

"공지 후 단독 작업"의 공지는 **GitHub Issue 또는 Draft PR** 로 한다. 락이 PR인 것과 같은 곳이어야 실행 가능하다.

## 4. git ↔ Maker 동기화

| 상황 | 해야 할 것 |
|---|---|
| **pull 하기 전** | **Maker를 끈다.** 끈 상태에서 pull하고 월드를 열면 **자동 동기화**된다 (가장 안전) |
| Maker를 켠 채로 pull 했다 | **`Reimport All`** |
| 개별 파일만 불러왔는데 오류 | **`Reimport All`** 로 해결 |
| 내 변경을 서버에 기록 | `File - Sync to Remote Workspace` — **개발책임자 이상만** |

동기화 명령: `Refresh`(변경분만) / `Reimport`(개별 스크립트·Dataset) / **`Reimport All`**(전체 반영 후 재로딩 — **git에서 받은 변경은 이걸**).

**머지 후 검증**: `Reimport All` → `maker_logs(kind:"build")` → **신규 경고 0**
⚠️ 빌드 콘솔은 **과거 항목을 보관한다.** `clear_logs` 로도 안 지워진다 → "경고가 0인가"가 아니라 **"경고가 늘었는가"** 로 판단한다.

## 5. 충돌과 롤백

### 5-1. 🔴 `.map` / `.ui` / `.model` 충돌 — 브랜치명을 명시한다

이 파일들은 `.gitattributes` 로 자동 머지를 꺼놨다. 충돌하면 **파일 전체가 충돌**한다. 둘 중 하나를 통째로 고른다.

```bash
git checkout 내브랜치이름 -- 경로/파일.map
```

```bash
git checkout main -- 경로/파일.map
```

> 🔴 **`--ours` / `--theirs` 를 쓰지 마라.** merge 중에는 `--ours` = 내 브랜치지만, **rebase 중에는 HEAD가 upstream이라 `--ours` = main 이 된다.** 의미가 정반대로 뒤집힌다. `.map` 은 통째로 고르는 파일이라 여기서 틀리면 **하루치 작업이 날아간다.**
> 그래서 ① **`pull --no-rebase` 고정**, ② 충돌 해결은 **항상 브랜치명 명시** 두 가지를 같이 지킨다.

버린 쪽 변경은 **Maker에서 다시 작업한다.** 이 복구 비용이 §2-1 소유권 규칙을 지켜야 하는 이유다.

### 5-2. `.csv` 충돌 — union이 양쪽 줄을 다 남긴다

자동으로 병합되지만 **확인이 필요하다**:
- **헤더가 두 줄이 되지 않았는가**
- **기본 키가 중복되지 않았는가** — git은 이걸 안 잡아준다

> 🔴 이 둘은 **자동 검사 스크립트**(§11)가 잡는다. **검사 없이 `merge=union` 을 쓰면 순손해다** — 시끄러운 충돌을 조용한 중복 키로 바꾸는 설정이기 때문이다.

### 5-3. `Global/SectorConfig.config`

**양쪽 `entries` 를 모두 남기고** 곧바로 동기화한다. Maker가 메모리 사본으로 이 파일을 되쓰는 이력이 있으니 편집 후 다른 조작을 넣지 않는다.

### 5-4. 🔴 롤백 — main에 깨진 게 머지됐고 서버에도 올라갔을 때

**가장 위험한 상황이다.** `git revert` 는 로컬 파일만 되돌리고 **MSW 리모트 워크스페이스의 리비전은 그대로**라, git 상태와 서버 상태가 갈라진다.

**순서를 지킨다 — git 먼저다.**

```bash
git revert <커밋해시>
```

1. **git revert** (또는 `git revert -m 1 <머지커밋>`)
2. **`Reimport All`** — 되돌린 로컬 파일을 Maker에 반영
3. `maker_logs(kind:"build")` 로 신규 경고 0 확인
4. **개발책임자가 `File - Sync to Remote Workspace`** — 되돌린 상태를 서버에 기록
5. 전원에게 공지하고 각자 pull + `Reimport All`

> ⚠️ **MSW Revision 롤백을 먼저 하면 안 된다.** 서버가 옛 상태로 돌아가고 로컬 git은 새 상태라 다음 동기화에서 되살아난다. **git → Maker → 서버** 순서를 지킨다.
> ⚠️ 4단계 중에는 **다른 사람이 `Sync to Remote` 를 하지 않는다.**

## 6. 기능을 추가하는 방법

### 6-1. 원칙 — **새 파일 + 데이터 행. 기존 파일 수정 0**

공용 파일에 "한 줄만" 추가하는 습관이 충돌의 대부분을 만든다. 대신 **이벤트로 붙인다.**

### 6-2. 이벤트로 붙이기

내 기능이 다른 곳의 신호를 들어야 하면 **내 파일에서 구독**한다:

```lua
@EventSender("Logic", "EventBus")
handler HandleMonsterKilled(MonsterKilledEvent event)
    -- 몬스터 처치 시 도감 진행도를 갱신한다.
end
```

발행자 파일은 건드리지 않는다. 발행자는 누가 듣는지 모른다.

### 6-3. 새 이벤트를 만들 때 — 🔴 순서가 있다

**계약서만 고쳐서 push하면 안 된다.** 정의 없이 구독하면 빌드 로그에 `Symbol not found` 가 난다.

발행자가 **한 번에 push하는 3종 세트**: ① `스키마-계약.md` B-3에 행 추가 ② `{도메인}/{Name}Event.mlua` ③ refresh로 생성된 `{Name}Event.codeblock`

**정의 PR이 먼저 머지되고 구독자 PR은 그 뒤다.** payload는 **append-only** — 추가는 안전하지만 이름 변경·삭제는 구독자를 깨뜨린다.

### 6-4. 새 UI 팝업

1. 담당 UIGroup `.ui` 에 노드 추가 (UIBuilder로만)
2. `FunctionalNpcCatalog.csv` 에 행 하나 (`UiGroupName` + `UiRoute`)

라우터 스크립트는 **고치지 않는다.** 데이터 주도다.
⚠️ **클릭 버튼을 UIGroup 루트 직속에 두면 실클릭이 안 먹는다.** 컨테이너에 중첩한다.

### 6-5. 🔴 아예 새로운 시스템을 만들 때

계약서 §1 **신규 시스템 등록 절차**를 따른다. **구현 전에 등록서 8항목을 문서로만 PR** 하고 머지된 뒤에 코드를 쓴다.

등록 대상 판정: 새 CSV 표 / 새 이벤트 / 새 열거값 / 상태 객체 필드 추가 / **남의 폴더 파일 수정** 중 하나라도 해당하면 등록한다.

## 8. 비밀정보

🔴 **`.mcp.json` 은 개인 파일이다.** API 토큰이 평문으로 들어 있다.

- `.gitignore` 에 있다. **절대 강제로 추가하지 않는다**
- 합류하면 `.mcp.json.example` 을 복사하고 **자기 토큰**을 넣는다
- 토큰을 커밋·채팅·문서에 붙여넣지 않는다
- 실수로 올라가면 **즉시 재발급.** 히스토리를 지워도 유출은 취소되지 않는다

## 9. 경로와 이름

- **clone 위치를 짧게** (`C:\msw\` 등). **전체 경로 255자**를 넘으면 동기화가 깨진다
- 금지: `< > : " / \ | ? *`, 예약어(`CON` `PRN` `AUX` `NUL` `COM1~9` `LPT1~9`), 이름 시작·끝의 마침표·공백
- **맵 이름은 영어** (공식 요구)
- **OS는 Windows 전용.** 경로가 한글이라 macOS를 섞으면 같은 파일이 두 개로 보인다

## 10. 테스트

### 10-1. 남의 작업에 영향 주지 않기

```lua
if _UserService.LocalPlayer.Name == "내닉네임" then
    TestComponent.Enable = true
end
```

🔴 **머지 전에 반드시 뺀다.** §3-2(6) 리뷰 항목이다. 안 빼면 출시 빌드에 남는다.

### 10-2. DataStorage

- **초기화는 본인 데이터만 지운다.** 다른 사람 데이터는 영향 없다
- ⚠️ **크레딧 과금이다.** `OnUpdate`·짧은 타이머에서 호출하지 않고 반복문에서는 `Batch*` 를 쓴다

### 10-3. "문법 오류 시 플레이 불가" 해제

`File - Setting - 만들기 - 스크립트` 에서 끄면 남의 스크립트 오류를 무시하고 테스트할 수 있다.
⚠️ **임시로만.** 계속 켜두면 고쳐야 할 오류를 못 보고 지나가 출시 후 터진다.

## 11. 자동 정합성 검사

Maker 없이 빌드 검증은 안 되지만, **조용히 깨지는 사고 대부분은 텍스트 대조로 잡힌다.** PR마다 돌린다.

| # | 검사 | 막는 사고 |
|---|---|---|
| 1 | CSV 헤더 ↔ 계약서 대조 | 두 월드의 같은 표가 갈라지는 것 |
| 2 | `MapName` ↔ `map/*.map` 루트 엔티티 이름 대조 | **스포너가 에러 없이 안 도는 것** (실제로 32건 발생) |
| 3 | 기본 키 중복 | **`merge=union` 이 만드는 중복 행** |
| 4 | `.csv` ↔ `.userdataset` 짝 존재 | 런타임에서 표가 안 읽히는 것 |
| 5 | 엔트리·폴더 이름 규칙 (금지 문자·예약어·255자) | LocalWorkspace 동기화 실패 |

> 🔴 **3번이 없으면 `merge=union` 은 순손해다.** 시끄러운 충돌을 조용한 중복 키로 바꾸는 설정이기 때문이다.

## 14. 합류 절차

1. **MSW 그룹 가입** → 등급 배정 (개발자 이상)
2. **clone** — 짧은 경로에 (`C:\msw\`)
3. 🔴 **`.gitattributes` 작동 확인** — 이게 안 먹으면 `.map` 이 **조용히 자동 머지**된다. 이 문서 §5가 통째로 무너지는 지점이다

```bash
git check-attr merge -- map/map01.map
```

   → **`merge: unset`** 이 나와야 한다. `merge: ours` 나 아무것도 안 나오면 멈추고 알린다.

```bash
git check-attr merge -- RootDesk/MyDesk/MonsterInfo.csv
```

   → **`merge: union`**

4. **push 훅 설치** — 관리자만 필수(서버 보호가 관리자를 강제하지 않는다). 개발자도 걸어두면 무해하다

```bash
git config core.hooksPath .githooks
```

5. `.mcp.json.example` → `.mcp.json` 복사 후 **자기 토큰** 입력
6. Maker에서 이 월드 최초 입장 → **폴더 선택창에서 clone 폴더 지정**
7. `Reimport All` → `maker_logs(kind:"build")` → **기준선 경고 개수를 PR 본문 양식에 쓸 수 있게 적어둔다**
8. 읽기: **이 문서** → [`스키마-계약.md`](스키마-계약.md) → 담당 도메인 GDD 절
9. 담당 폴더·이벤트 도메인 배정받기 (§2-2)
