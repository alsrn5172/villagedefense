## 0. 공통 규약

### 0-1. CSV 열 규약

1. `RootDesk/MyDesk/{Name}.csv` + **`{Name}.userdataset` 쌍 필수.** csv만 있으면 런타임에서 안 읽힌다
2. **첫 열이 기본 키.** 복합키는 키 열들을 **앞에 연속 배치**하고, 두 값을 합친 문자열 열을 따로 만들지 않는다
3. 🔴 **`#Note` 는 항상 마지막 열.** 새 열은 반드시 **`#Note` 앞에** 넣는다
4. 🔴 **열 중간 삽입 금지. 뒤에 추가만.** 중간에 넣으면 기존 행의 값이 전부 한 칸씩 밀린다
5. **빈 칸 = 기본값.** 로더는 모든 열에 `tonumber(...) or 기본값` / `or ""` 폴백을 넣는다. 이게 "그 열을 모르는 쪽에서도 안 죽는" 확장 계약의 실체다
6. 열 이름 **PascalCase**, 약어도 첫 글자만 — **`Hp` `Mp` `Ap` `Id`**
7. Boolean 은 소문자 `true` / `false`
8. 단위 — 좌표 **world unit**(1 unit = 100px), 시간 **초**, 확률·배율 **소수**
9. 🔴 **헤더 변경은 공지 후 단독 작업.** `.csv` 는 git `merge=union` 이라 헤더가 두 줄 되면 조용히 깨진다

> ✅ CSV는 MSW가 **로컬 직접 편집을 공식 허용한 유일한 데이터 형식**이다. 데이터를 CSV로 밀어 넣을수록 협업이 안전해진다.

### 0-5. 상태 객체 필드 규약

- **도메인 접두사 필수** — `account_*` / `match_*` / `village_*`
- 🔴 **매치 재화와 계정 재화를 같은 필드·같은 저장 키에 합치지 않는다**
- `AccountProfile` 은 **`SchemaVersion` 필수**, M1 최초값 `1`
- 영구 저장 진입점은 **`PlayerDBManager` 하나뿐**
- 🔴 **저장은 read-modify-write.** 통째로 덮어쓰면 다른 도메인 필드가 지워진다
- ⚠️ **선언 없는 `self.<name>` 대입은 런타임 에러**(`cannot set <name>, no such field`) → `property` 선언 또는 `self._T.<name>`

상태 객체 (GDD §4.10): `AccountProfile`(영구) · `MatchLobbyState` · `MatchSession` · `MatchPlayerState` · `VillageMatchState` · `MinionFlowState`

## 1. 🔴 신규 시스템 등록 절차

**문제**: 이 계약서는 **이미 아는 것**만 다룬다. 아무도 계획하지 않은 새 시스템(예: 플레이어 스킬 시전)은 협약 밖에서 태어나 각자 방식으로 만들어지고 **합칠 때 터진다.** 협약을 아무리 잘 맺어도 "새로 만드는 것"에 대한 협약이 없으면 소용없다.

**해결**: 새 시스템은 **구현 전에 등록을 먼저 머지**한다. 이벤트 3종 세트(§B-2)의 확장판이며 같은 논리다.

### 등록서 8항목

| # | 항목 | 이게 없으면 merge에서 무슨 일이 나나 |
|---|---|---|
| 1 | 시스템 이름 + **소유 폴더** | 폴더가 갈려야 `.mlua` 충돌이 원천 차단된다 |
| 2 | 새 CSV 표 — 파일명 · 헤더 · 기본 키 (없으면 "없음") | 이름·열이 미리 갈려야 `merge=union` 이 안전하다 |
| 3 | 새 이벤트 — **발행할 것 / 구독할 것** | 미리 선언돼야 상대가 구독할 수 있다. 나중에 하면 **발행자 파일을 고쳐야 한다** |
| 4 | 새 열거값 | §0-2 정본에 합류. 같은 개념을 다른 값으로 쓰는 걸 막는다 |
| 5 | ID 대역 / 문자열 접두사 | union 머지는 **ID 중복을 안 잡아준다** |
| 6 | 저장 필드 — 어느 상태 객체에 무슨 필드 + 접두사 | 통짜 덮어쓰기로 남의 필드가 지워지는 사고를 막는다 |
| 7 | 새 `.model` / `.ui` 파일명 | 새 파일이면 안전, 기존 파일이면 소유권 협의 |
| 8 | 🔴 **건드리는 기존 파일 전부** | **여기가 유일한 협의 지점이다** |

### 절차

1. 만들 사람이 이 문서에 **등록 항목을 추가**해 PR을 올린다 — **코드 없이 문서만**
2. 상대는 **8번**과 **2·5번**만 본다
3. 머지된 뒤에 구현을 시작한다

> **8번이 비어 있으면 = "새 파일만 만든다" = 사실상 통과.** 8번에 뭐가 있으면 거기만 이야기하면 된다.

### 등록 대상 판정

아래 중 하나라도 해당하면 등록한다 — **새 CSV 표** / **새 이벤트** / **새 열거값** / **상태 객체 필드 추가** / **남의 폴더 파일 수정**.
해당 없으면(내 폴더 안에서 새 `.mlua` 만 추가) 그냥 만든다.

### 등록된 시스템

| 시스템 | 소유 | 상태 |
|---|---|---|
| 스킬 시전 · 스킬 UI | 상대 (`Skill/`) | ⬜ **등록서 대기** |
| 전직 | 상대 (`Job/`) | ⬜ **등록서 대기** — 🔴 **10레벨 전직이 마을 획득의 전제**라 사용자 골격의 크리티컬 패스에 있다. `JobChangedEvent` → 코어 연결 자격 부여 인터페이스가 최우선 협의 항목 |

# A부. 데이터 표

## A-1. 현존 표 8종

### A-1-1. 🔴 정본화 대상 2종 — 두 월드가 갈라져 있다

병합 전 상태: 밍키타 `MonsterInfo` 9열(`…ModelId,MoveSpeed,JumpForce`) vs 안농 10열(`…Level,MaxHP,Exp,…,MoveType,AiType`). `MaxHP` 가 4번째에 삽입돼 뒤 열이 전부 밀렸고 `#Note` 위치도 다르다. `MonsterCatalog.mlua` 도 읽는 열이 서로 다르다.

**정본 (합집합. 안농 열 순서 + 밍키타 2열을 뒤에):**

```
MonsterInfo.csv
Id,Name,Level,MaxHp,Exp,CoinMin,CoinMax,ModelId,MoveType,AiType,MoveSpeed,JumpForce
```

| 열 | 타입 | 기본값 | 설명 |
|---|---|---|---|
| `Id` | string(정수 문자열) | — | **기본 키.** §0-4 |
| `Name` / `Level` | string / integer | `""` / `0` | 표시용 |
| `MaxHp` | integer | `1` | 밍키타 출신 행은 빈칸 → 기본값 |
| `Exp` · `CoinMin` · `CoinMax` | integer | `0` | 처치 보상 |
| `ModelId` | string | `""` | 스폰할 `.model` id |
| `MoveType` · `AiType` | enum(소문자) | `walk` / `wander` | §0-2 |
| `MoveSpeed` · `JumpForce` | number | `-1` | `-1` = 모델 기본값. 안농 출신 행은 빈칸 |

```
MapMonsters.csv
MapName,MonsterId,X,Y,SpawnerId,SpawnId,SpawnCount,RespawnSeconds,Enabled,#Note
```

`MapName`+`MonsterId` 복합키. `X`/`Y` world unit. `SpawnerId` = `<MapName>_SP001`, `SpawnId` = `<SpawnerId>_M<MonsterId>`. `SpawnCount` 만큼 독립 슬롯, 각 슬롯이 `RespawnSeconds` 뒤 한 마리 재생성.

> 🔴 정본화 시 **`MonsterCatalog.mlua` 도 한 벌로 통일**하고 신규 열 전부에 §0-1(5) 폴백을 적용한다.

# B부. 이벤트

## B-1. EventBus

**왜**: 직접 호출은 "A가 B를 호출 → A의 파일이 B를 안다 → 구독자를 추가할 때마다 발행자 파일을 고쳐야 한다"가 된다. 여러 명이 붙으면 그 발행자 파일이 충돌 지점이 된다.

> **기능 추가 = 새 파일 + 데이터 행. 기존 파일 수정 0.**

### 위치와 API

`RootDesk/MyDesk/Core/EventBus.mlua` — `@Logic`. 서버·클라 양쪽에 각각 존재.

```
_EventBus:Publish(ev)                              -- 같은 쪽 구독자에게 발행 + 디버그 로그 1줄
_EventBus:PublishToClients(name, payload)          -- @ExecSpace("Multicast")
_EventBus:PublishToUser(name, payload, forUserId)  -- @ExecSpace("Client")
```

### 발행

```lua
local ev = MonsterKilledEvent()
ev.MonsterId = 1001
ev.MapName = "Henesys_Hunt_HillNorth"
ev.KillerUserId = userId
_EventBus:Publish(ev)
```

🔴 **발행자는 구독자를 모른다.** 발행자 파일에 구독자 이름이 등장하면 규칙 위반.

### 구독 — 구독자 자기 파일에서

**정적 (권장, 정리 불필요):**

```lua
@EventSender("Logic", "EventBus")
handler HandleMonsterKilled(MonsterKilledEvent event)
    -- 몬스터 처치 시 도감 진행도를 갱신한다.
end
```

**동적 (조건부로 붙였다 뗄 때만):** `_EventBus:ConnectEvent(...)` + **`OnEndPlay` 에서 `DisconnectEvent` 필수**, 핸들은 **`property any`** 에 보관.

⚠️ 주의
- `@EventSender` → `handler`, `ConnectEvent` → `method void`. **섞으면 컴파일되고 영영 안 불린다**
- `ConnectEvent` 는 Entity/Logic/Service 에만 있다 → **버스가 Logic이라 Component 안에서도 붙일 수 있다**(버스를 두는 실용적 이점)
- 동적 구독 핸들을 지역 변수에 두면 GC된다
- `handler` 는 예약어 → `eventHandler`

### 서버 / 클라 경계

이벤트는 **같은 쪽 안에서만 전파된다고 가정한다.** `EventType` 객체는 **RPC를 넘지 못한다**(허용 타입 목록에 없다).
반대편에 알려야 하면 `PublishToClients(name, payload)` 로 **이름 + 문자열 payload** 를 넘기고 받는 쪽에서 재구성해 `Publish` 한다. 재구성 표는 `EventBus.mlua` 안에 두되 **크로스가 실제로 필요한 이벤트만** 등록한다.

> ⚠️ **미확인**: 실제 전파 범위와 `EventType` 파라미터 허용 여부는 EventBus 첫 구현 때 로그로 확인하고 **결과를 여기에 적는다.**
>
> 확인 결과: _(EventBus 구현 시 기입)_

## B-2. 작성 규약과 도입 순서

한 이벤트 = 한 파일, **발행 도메인 폴더**에.

```lua
@Event
script TowerDestroyedEvent extends EventType
    property string MatchId = ""
    property string VillageId = ""
    property string Stage = ""      -- TOWER1 / TOWER2 / SUPPRESSOR
end
```

1. payload는 **원시 타입과 문자열만.** `any`/table 금지 — RPC로 넘기면 `[LEA-3036]` 이고 **빌드에 안 잡힌다.** 목록은 문자열 직렬화
2. 열거값은 **문자열**
3. 🔴 **중복 방지 키를 포함** — `SettlementId` 등. 같은 결과를 두 번 반영하면 안 된다
4. 🔴 **payload는 append-only.** 필드 추가는 안전(기존 구독자는 모르는 필드를 무시). **이름 변경·삭제는 구독자를 깨뜨린다** → 공지 후 단독 작업

**도입 순서** — 이 문서만 고쳐서 push하면 안 된다. 정의 없이 구독하면 빌드 로그에 `Symbol not found` 가 난다.
발행자가 **3종 세트를 한 번에** push: ① 이 문서 B-3에 행 추가 ② `{도메인}/{Name}Event.mlua` ③ refresh로 생성된 **`.codeblock`**(EntryKey가 `codeblock://{소문자명}` 이라 결정론적 → 커밋해도 안전).

🔴 **정의 PR이 먼저 머지되고, 구독자 PR은 그 뒤다.**

## B-4. 도메인 ↔ 폴더 ↔ 담당

| 도메인 | 폴더 | 담당 |
|---|:---:|:---:|
| EventBus | `Core/` | A |
| 매치 진행 · 맵 이동 · 난이도 · 승패 · 계정 | `Match/` | A |
| 코어 · 소유권 | `Village/` | A |
| 미니언 흐름 · 전선 · 포탑 | `Lane/` | A |
| 파병 | `Dispatch/` | A |
| 몬스터 · 엘리트 | `Monster/` | A |
| 보스 · 발록 | `Boss/` | A |
| 맵 · 포탈 · 월드맵 | `Map/` | A |
| NPC · 상호작용 | `Npc/` | A |
| 재화 | `Economy/` | A |
| 기록 · 보상 | `Progression/` | A |
| **스킬 · 전직** | **`Skill/` `Job/`** | **B** |

기존 폴더(`Catalog/` `Spawn/` `Faction/` `Farm/` `Summon/` `Camera/` `Terrain/` `WorldMap/`)는 유지하되, 이관 계획은 §협업-규칙에 따른다.
