## B-3. 수비대 1묶음 마릿수 🔴 코드 불일치

기획(추가기획1 §1-2)은 **1묶음 ≈ 10마리**(몬스터별 크기는 데이터)이고 **모집 비용이 재화 8개**인데,
코드가 그 **8을 마릿수로** 써버렸다.

```
LaneStateService.mlua:633   SpawnBundle(v.id, monsterId, mul, 8, ...)   ← 8"마리"
코드 주석                    "묶음(8마리)당 지역재화 8개"                  ← 두 8을 혼동
```

몬스터별 묶음 크기 표(`MonsterRecruit`)가 아직 없어서 지금 고쳐도 임시 상수다.

| # | 항목 | 필요한 값 | 답 |
|---|---|---|---|
| B-3-1 | 기본 묶음 크기 | 임시 상수로 쓸 값 (기획 기준 10) | |
| B-3-2 | 몬스터별 묶음 크기 | `MonsterRecruit` 표 — 몬스터별 마릿수 (예: 뿔버섯 15) | |
| B-3-3 | 묶음 → 칸 환산 | 반올림/올림 규칙 (추가기획1 §5 미결 1번) | |

### 구현 시 확인된 사실 (Codex 교차검증 2회 일치 · 2026-09-10)

- 🔴 **`_UtilLogic.ServerElapsedSeconds` 는 오프라인 충전에 못 쓴다.** 월드 재시작 때 0으로 돌아간다.
  절대 시각은 **`DateTime.UtcNow`**(`Elapsed` 는 밀리초)이고 **이 저장소에 사용처가 0건**이다 — 여기서 처음 깐다
- 🔴 **`AccountStorageLogic.SchemaVersion` 을 `1` → `2` 로 올려야 한다.** 필드가 늘어나므로 이미 저장된
  계정 JSON 에는 새 키가 없다 → 역호환 기본값 분기 필수. **계정 영구 재화라 잘못 읽으면 심장이 사라지거나 공짜로 생긴다**
- **정산 ID(중복 차감 방지) 패턴이 저장소에 없다.** 선례는 `AccountData.saveGeneration` · `PlayerDBManager.saving[]` ·
  `MatchLobbyGateway.m.gen` · `FarmReward.Rewarded` 네 가지다
