## 1. 사용자 원문 (2026-10-15 · 그대로)

1. 9분 18분 27분에 각각 다섯 마을중 랜덤으로 사냥터1, 사냥터2, 사냥터3 중 하나가 그 판에서 영구적으로 파괴된 빅토리아아일랜드맵으로 변함. 변한다고해도 크게 변하는건 아니고, 맵배경이 파괴된헤네시스/파괴된페리온으로 변하고, 몬스터들이 변형된 달팽이, 슬라임, 주황버섯, 리본돼지, 스텀프, 와일드보어로 바뀜.(순서대로2개씩 사냥터1,2,3에 등장하게됨) 해당 몹들은 기존 사냥터 몹보다 각각 레벨이 2씩 높고, 모든 지역의 재화를 드랍하고(드랍확률100퍼센트), 경험치를 기존몹보다 각자 50퍼센트 더 줌.(21렙->23렙된 변형된스텀프는 21렙보다50퍼더줌) 꿈의 조각도 주고, 빅토리아 주화도 줌(드랍률10퍼 고정).
2. 1번패치로인해 스틸이 게임에서 유효한 전략이 됨. 9분 18분 27분에 스틸하고, 27분에는 내친김에 보스까지 스틸할수있음.
3. 변형된몹들은 각자 대체되는 몹들에비해 2렙증가, 경험처50퍼, 체력은 그대로, 공격력은1.5배.
4. 튜토리얼에서 지역보스(머쉬맘)잡으러 가기전에 9,18,27분때에 파괴된 빅토리아아일랜드 지형이 생긴다면서 지도켜서 커닝시티에 생긴거 보여주고 직접가서(순간이동시켜주고) 바뀐 몬스터 구경시켜주고 일반몬스터는 주지않는 모든지역재화, 꿈의조각,빅토리아주화를 다주고 경험치를 더 준다고 언급. 저런 지형이 생기면 놓치지않고 가서 사냥터 사수하는게 이득이라고 강조.=다른지역보스를위한초석도 된다고 해야함.
5. 파괴된 어쩌구가 생기기 30초전에 어디마을에 생길지 우측상단 메뉴UI예고하고, 생긴뒤에는 월드맵에서 해당맵정보도 바뀌고(어떤몹나오는지정보) 해당맵노드도 불타오르는 표시가 나오도록 하자.

## 6. 권장 설계 (참고 · 더 나은 길이 있으면 이유를 적고 바꿔도 된다)

- 서버 `@Logic` 하나(예: `Match/DestroyedVictoriaService.mlua`): 매치 시작에 상태 초기화 → 경과 8:30 · 17:30 · 26:30 에 대상(마을 · 사냥터) 고르고 예고(모든 클라) → 9:00 · 18:00 · 27:00 에 적용. 적용 = (a) 그 맵 배경 교체(서버가 동기화되는 값으로) (b) 기존 몹 정리 후 변형 몹으로 스폰 표 교체 (c) 변형 몹 능력치 · 드랍 덮어쓰기 (d) 월드맵 정보 · 노드 표시 상태 동기화(상태 문자열 하나를 @Sync 또는 클라 RPC 로 · table 을 ExecSpace 너머로 넘기지 말 것 — 문자열로 직렬화).
- 수치 · 표: 기존 CSV **헤더는 바꾸지 않는다**(바꾸려면 이슈 #40 공지 후 단독 · `merge=union` 주의). 새 표가 필요하면 새 CSV 보다 코드 상수 표(`BossSkillRunner.SummonRule` 처럼)가 Maker 등록 없이 안전하다. 변형 몹을 `MonsterInfo.csv` 새 **행**으로 넣는 건 괜찮다(헤더 그대로).
- 변형 몹 모델: 기존 몹 모델을 ModelBuilder 로 복사해 그림만 바꾸는 방식(1.0.9 `monster4230400boss` 와 같은 길 · `RootDesk/MyDesk/Models/Monsters/`). 새 `.model` 은 Maker refresh 뒤 등록된다(사용자).
- 드랍 100% · 10% 는 이 몹들에만(사냥터 공용 드랍 표는 안 건드림). 보상 귀속은 기존 규칙(최다 피해 · 막타 등) 그대로.
- 예고 · 적용은 로그를 남긴다(`[DestroyedVictoria] notice/apply village=... map=...`) — 사용자가 Maker 로그로 확인한다.
