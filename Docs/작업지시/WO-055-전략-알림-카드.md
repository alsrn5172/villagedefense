## 2. 이미 정한 것 (사용자 2026-10-15)

- 띄우는 곳 = 화면 오른쪽 알림 카드 = `Onboarding/TipController.mlua` · `ui/TipGroup`(제목 · 본문 2줄 · 아이콘 · '자세히' · 닫기 · 12초 · 카드 사이 25초 · 알림마다 매치 한 판에 한 번 — 이미 그렇게 돈다). 위쪽 네비게이션(PortalNav) 아님.
- 🔴 **대상 = 모든 난이도 · 모든 사람**(안내를 꺼도 뜬다). 기존 카드 8개(potion · phase2 · phase3 · denied · weapon · spjob · ap · sp)는 **지금처럼 ★1 + 안내 켬일 때만** — 새 4개만 이 문(`armed` · `_GuideUIController.visible` 검사)을 건너뛴다(표에 `always = true` 같은 표시 · 줄 · 간격 · 안전 검사 `IsSafe` · 사망 · 관전 규칙은 같이 쓴다).
- 특수재화 = `MAPLE_SEAL_STONE`(단풍 봉인석 · 보스 드랍) · 1개 = 앱솔랩스 1부위 교환(`CraftRecipe.csv` `RECIPE_ABSOLAB_*` · 장비 상인).

## 3. 알림 4종 (조건 · 문구 초안 — 문구는 카드 2줄 안 · 키는 "(V 또는 우측 상단)" 꼴 · 모바일 전용 문구 금지)

| key | 조건 | 제목 / 본문 초안 |
|---|---|---|
| `gearweak` | **보정 전투력** × 10 ≤ **지금 레벨에 맞는 몬스터 최대 HP** (= 스킬 10번으로 못 잡음) | 장비가 약해요 / 현재 레벨에 비해 장비가 약한 것 같아요!\n장비를 구매하거나 강화해야 사냥을 수월히 할 수 있어요. (사용자 문장 그대로) |
| `upgrade` | 내 마을 시설을 **연달아 3단계 이상 강화할 주화**가 있다 — 대상 순서: 포탑(가장 낮은 것) → 포탑이 모두 최대면 억제기 → 그다음 넥서스 | 시설 강화 타이밍 / 주화로 ○○을(를) 3단계 이상 올릴 수 있어요.\n마을 관리(…)에서 강화해요. (○○ = 그때 대상) |
| `recruit` | 수비대를 **3묶음 이상 모집할 재화**가 있다 | 수비대 모집 / 수비대를 3묶음 이상 모집할 수 있어요.\n모집해서 마을을 지키는 건 어때요? |
| `gear30` | 레벨 ≥ 30 인데 끼고 있는 장비 중 **착용 레벨 ≤ 20** 이 하나라도 있다 | 30레벨 장비 / 30레벨 장비를 끼는 건 어때요?\n장비 상인에게서 사거나 만들 수 있어요. |
| `absolab` | 가방에 `MAPLE_SEAL_STONE` ≥ 1 | 앱솔랩스 / 특수 재화(단풍 봉인석)가 생겼어요!\n장비 상인에게서 특수 장비 앱솔랩스로 바꿀 수 있어요. |

- `upgrade` 와 `recruit` 는 사용자 원문상 두 알림이다(시설 하나 · 수비대 하나).
- 아이콘은 기존 알림 아이콘 · 스킨에서 고른다(새 업로드 금지).

## 4. 판정 재료 (코드 위치 — 직접 확인)

- **보정 전투력**: `Stat/StatService.mlua` `CalcCombatPower(u)` = 기본 × 치명 배율 × 명중 배율 × **방무 배율** × 직업 계수(1.0.7 §6). 사용자 정의 = "데미지 기댓값에서 **방어율 무시 몫만 뺀** 값" → 같은 식에서 방무 배율만 1 로 둔 값을 새로 계산(기존 전투력 · 전광판 값은 그대로). 서버 값이다.
- **지금 레벨에 맞는 몬스터 HP**: 사냥터 단계(`DropTableLogic` 레벨 문턱 ≤14 · ≤21 · 그 위) · `MapMonsters.csv`(`LevelOverride`) · `MonsterInfo.csv` · `Catalog/MonsterCatalog.mlua`(`LevelHp` · `HpLevelMul`). 권장 정의: **플레이어 레벨 이하에서 가장 레벨이 가까운 사냥터 몬스터의 최대 HP**(레벨 배율 적용 · ★ 배율 있으면 포함) — §5 질문 1 로 확정.
- **시설 강화**: `Lane/LaneStateService.mlua` `RequestTowerAction`(upgrade) · `TowerConfig.csv`(`UpgradeCost` 티어 · 최대 단계) · 주화 = `SummonManager` econ(빅토리아 주화 카운터). "3단계 이상" = 대상 시설의 다음 3단계 비용 합 ≤ 보유 주화.
- **수비대 모집**: 마을 관리 창(`Npc/VillageDefenseUIController.mlua`) · 모집 서비스(이름으로 찾기: Recruit · Defender) · 묶음 비용(지역 재화 · 메소 등). "3묶음" = 비용 × 3 ≤ 보유량.
- **착용 장비 레벨**: `ItemInfo.csv` 착용 레벨 열 · `EquipService`(장착 목록) · 클라 미러 `InventoryUIController.equipped`.
- **봉인석 개수**: `InventoryService:CountItem(userId, "MAPLE_SEAL_STONE")`.
- 권장 구조: 판정 대부분이 서버 값이라 **서버 `@Logic` 하나(예: `Onboarding/AdviceService.mlua`)가 매치 중 유저마다 2 ~ 3초 간격으로 판정** → 맞으면 그 유저 클라에 `TipController` 의 Client 메서드로 key 문자열 하나를 보낸다(table 을 ExecSpace 너머로 넘기지 말 것). 클라 `TipController` 가 `Want(key)` 로 줄에 세운다(한 판 한 번 = 기존 `done` · 새 판 = `OnMatchStart` 가 비움). 서버 쪽도 유저 · 매치마다 보낸 key 를 기억해 같은 판에 다시 안 보낸다(매치 시작 때 비움 · `MatchSerial` 등).
- 튜토리얼(1인 휘발 룸 · `TutorialDirector.active`) 중에는 새 카드를 띄우지 않는다(튜토리얼 장면과 겹침).

## 5. 구현 전에 사용자에게 물어 정할 것 (AskUserQuestion 한 번 · 표 · 예시는 질문 앞 본문에)

1. "지금 레벨에 맞는 몬스터" 기준: (권장) 내 레벨 이하에서 가장 가까운 레벨의 사냥터 몹 / 내 레벨대 사냥터의 가장 센 몹 / 내 레벨대 사냥터 몹 평균.
2. "스킬공격 10배": 보정 전투력 × 10 ≤ 몬스터 HP 면 알림(= 10번 쳐도 못 잡음)으로 읽었다 — 맞는지.
3. 시설 · 수비대 알림 문구에 대상 이름 · 개수를 넣을지(예: "포탑을 3단계 이상") 고정 문구로 둘지.
- 나머지(카드 위치 · 한 판 한 번 · 대상 = 모든 사람 · 특수재화 = 단풍 봉인석)는 정해졌다 — 다시 묻지 않는다.

## 6. 사용자가 Maker 에서 확인할 것 (끝에 이 목록을 갱신해서 남긴다)

- 주화 · 재화를 개발 리모컨/서버 Lua 로 채워 `upgrade` · `recruit` 카드.
